# How to Detect AI Bots Without Blocking Googlebot

## Overview

Your website is receiving automated requests. Some are from search engines trying to index your pages. Others come from AI crawlers, monitoring tools, scrapers, or malicious scripts. The challenge isn't identifying every automated request. It's knowing which bots should be allowed and which ones deserve closer inspection. Block everything that looks automated, and you risk blocking Googlebot or AI search crawlers. Trust every request claiming to be Googlebot, and anyone can bypass your basic filtering rules. So how do you detect AI bots without blocking legitimate crawlers? In this guide, we'll cover the different types of bots, build a working bot detection tool using Node.js, test it in VS Code, and explore how IP intelligence can help classify suspicious traffic. What you'll build: A local Express server that recognizes bot user-agent strings, plus an optional IP Security lookup script that can be tested with sample data. The basic project is free. No paid API subscription is required to complete the first part. 1. Understand the Different Types of Bots Not every bot visiting your website is trying to cause problems. Here's a quick comparison. Bot Purpose Typical handling Googlebot Search engine indexing Allow after verification Bingbot Search engine indexing Allow after verification OAI-SearchBot ChatGPT search discovery Follow your AI search policy GPTBot AI model-related crawling Follow your training crawler policy ChatGPT-User User-triggered page retrieval Evaluate separately Uptime monitoring bots Website availability checks Allow recognized services Malicious scrapers Unauthorized extraction or abuse Rate-limit or block when justified OpenAI, for example, operates different crawlers for different purposes. According to OpenAI's official documentation , OAI-SearchBot is used for ChatGPT search, while GPTBot crawls content that may be used for training AI models. ChatGPT-User is different again. It can retrieve web pages in response to a user's action. The distinction matters because you may want your articles discoverable in AI search without allowing every type of automated crawling. 2. Why User-Agent Detection Isn't Enough One of the easiest ways to recognize a bot is through its HTTP User-Agent header. For example, a request might contain: Googlebot/2.1 Or: GPTBot/1.4 Your server can inspect that header and classify the request. But there's a problem. Anyone can send a request pretending to be Googlebot: curl -A "Googlebot" https://example.com The -A option tells curl to send a particular user-agent string. It doesn't make the request come from Google. That's why we need to distinguish two concepts: Bot identification: What software does the request claim to be? Bot verification: Does the source actually belong to the claimed operator? Let's start with identification. 3. How to Verify Real Googlebot Traffic Google recommends verifying its crawlers using DNS or published crawler IP ranges. The DNS verification process works like this: Extract the actual client IP address. Perform a reverse DNS lookup. Check whether the hostname ends with an approved Google crawler domain. Perform a forward DNS lookup on that hostname. Confirm the original IP is among the returned addresses. For example, Google's documentation shows crawler hostnames under: googlebot.com But you shouldn't trust an arbitrary hostname simply because it contains the word google . The hostname must match Google's documented patterns, and forward DNS must confirm the original address. Google also publishes official crawler IP ranges. You can find the complete procedure in the Google crawler verification documentation . What about OpenAI crawlers? OpenAI publishes IP ranges for different crawlers: OAI-SearchBot IP ranges GPTBot IP ranges ChatGPT-User IP ranges If a request claims to be GPTBot, you can compare its actual source IP against the appropriate published ranges. For production systems, you should regularly refresh these lists and correctly handle IPv4 and IPv6 CIDR ranges. Also, when your application sits behind a reverse proxy, configure Express's trust proxy setting for your actual trusted proxy infrastructure. Don't blindly trust an incoming X-Forwarded-For header. 5. Detect Unknown Bots Using IP Intelligence Verifying Googlebot is useful because Google provides official verification methods. But what about a bot that doesn't identify itself? Imagine an unknown client makes thousands of requests to your website. It doesn't claim to be a search crawler. Its user-agent looks ordinary, and you don't recognize the IP address. In this situation, IP intelligence can provide useful context. For example, IPGeolocation.io's IP Security API provides information about whether an IP address has been associated with: Automated bot activity Known legitimate bots Brute-force attacks VPNs and proxy networks Tor exit nodes Cloud hosting providers Other security risks The API can return fields such as: Field Purpose is_bot Identifies bot activity associated with the IP bot_type Describes the bot activity category bot_operator_name Identifies a known operator when available is_known_good_bot Indicates a recognized legitimate bot bot_confidence_score Confidence score for bot activity threat_score Overall IP risk score is_known_attacker Indicates known attacker activity These signals help distinguish a recognized crawler from suspicious automation. An important limitation is that IP intelligence classifies an address based on available intelligence. It doesn't prove that every individual request from that address came from the same software. Is the IP Security API free? The IP Security Lookup feature requires a paid subscription. According to the current documentation, each successful security lookup costs two API credits. The provider also describes an option to request trial access through customer support. You can still follow the next example without paid access by using mock security data. 6. How to Decide Which Bots to Allow or Block Once you have identification and risk signals, you need a policy. A sensible starting point looks like this: Traffic Suggested response Verified Googlebot Allow indexing of public pages Verified OAI-SearchBot Follow your AI search visibility policy Verified GPTBot Follow your AI training access policy Known monitoring service Allow expected monitoring traffic Unrecognized automated traffic Monitor or rate-limit Known malicious activity Investigate or block Uncertain classification Collect more signals Don't automatically block every datacenter IP. Many legitimate crawlers operate from cloud infrastructure. Similarly, don't automatically trust a bot simply because its IP reputation looks good. For sensitive endpoints such as login forms, combine IP intelligence with request frequency, failed-login patterns, rate limits, and other behavioral signals. The examples in this article return suggested actions. They don't implement firewall rules or automatically block requests. That's intentional because a production blocking decision requires stronger verification and a tested false-positive policy. 8. Use robots.txt to Manage AI Crawlers Some crawler operators support separate instructions for different purposes. For example, you might allow Googlebot and OAI-SearchBot while asking GPTBot not to crawl your website. Your robots.txt file could include: User-agent: Googlebot Allow: / User-agent: OAI-SearchBot Allow: / User-agent: GPTBot Disallow: / This tells compliant crawlers that: Googlebot may crawl public content. OAI-SearchBot may crawl public content. GPTBot should not crawl the site. Remember that robots.txt is not a security mechanism. Malicious bots can ignore it. OpenAI also notes that user-triggered ChatGPT-User requests are different from its automatic crawlers, and ordinary robots.txt rules may not apply in the same way. When you need actual enforcement, use verified network identity and appropriate server-side access controls. 9. Common Bot Detection Mistakes Trusting user-agent strings Anyone can claim to be Googlebot. A matching string isn't proof of identity. Blocking every cloud IP Legitimate crawlers, monitoring tools, and real users may access your website from cloud infrastructure. Treating all AI bots identically AI search crawlers, training crawlers, and assistant-triggered fetchers serve different purposes. Making an IP lookup for every request External API calls introduce latency and cost. Cache appropriate results and avoid unnecessary repeated lookups. Blocking based on a single risk indicator A flagged IP address doesn't necessarily prove malicious intent for every request. Use additional signals and provide a way to investigate false positives. Ignoring API failures Your website shouldn't become unavailable just because a security intelligence API temporarily fails or your account reaches its limits. Choose an explicit failure policy. For public informational pages, continuing with monitoring may be reasonable. Sensitive endpoints may require stricter controls. 10. Frequently Asked Questions How do I detect AI bots on my website? Start by examining user-agent strings and request logs. Verify recognized crawlers using their operators' published IP ranges or DNS verification methods. For unknown traffic, combine behavioral analysis with IP intelligence. Can someone fake Googlebot? Yes. User-agent headers can be changed freely. Google recommends verifying crawler requests using its documented DNS procedure or official IP ranges. Can I test bot detection without paying for an API? Yes. The basic Node.js user-agent detector in this article runs locally without an API key. You can also test the classification logic using simulated security data. Real IP Security lookup results require the appropriate API subscription or trial access. Will blocking AI training crawlers affect Google rankings? Blocking GPTBot through its specific robots.txt rule doesn't directly block Googlebot. However, broad server or firewall restrictions could accidentally affect search engine access. Is IP intelligence enough to identify malicious bots? No. It's one useful layer. Combine it with identity verification, request rates, behavioral patterns, and your website's own access policy. Final Thoughts Detecting AI bots isn't simply about checking whether a request contains the word bot . You need to understand the traffic, identify known crawlers, verify their identities when necessary, and make decisions based on both reputation and behavior. In this guide, we built a basic bot identifier, tested Googlebot and AI crawler user-agent strings, and added an optional IP Security classification example. The most important lesson is simple: Don't block a request just because it looks automated, and don't trust a request just because it claims to be legitimate. Verify what you can, monitor what you can't, and apply policies that protect your website without unnecessarily restricting search engine access.
