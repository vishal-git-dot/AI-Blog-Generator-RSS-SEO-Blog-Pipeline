The most expensive mistake in a site migration is quiet: old URLs that used to get traffic and backlinks start returning 404 on the new site, and nobody notices for weeks. Search Console only shows you some of them, and only after Google has crawled the broken pages. The fix is boring and cheap: before you switch, write down every URL the old site ever had, then check each one against the new site and add a 301 for anything that breaks. The catch is getting that list. Your CMS knows today's pages, not the /blog/2019/old-slug from three redesigns ago that a partner still links to. The Internet Archive does know, and it has a free API for it. Step 1: list every archived URL with the Wayback CDX API The CDX server returns one row per capture. Limits The archive only knows pages it crawled. Brand-new or blocked (robots.txt, login) pages won't be there; combine this list with your sitemap and analytics top pages. Query strings are kept as separate paths. If your old site used ?page=2 style URLs, decide which ones deserve redirects. HEAD requests are blocked by a few servers; switch to GET if you see 405.
