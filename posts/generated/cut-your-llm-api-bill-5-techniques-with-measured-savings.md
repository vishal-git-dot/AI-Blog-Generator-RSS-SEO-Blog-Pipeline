# Cut Your LLM API Bill: 5 Techniques With Measured Savings

## Overview

Cutting your LLM API bill means paying only for the tokens that change the answer. Most teams pay full price for the same system prompt thousands of times a day, run flagship models on trivial tasks, and let reasoning tokens run unchecked. Five techniques, prompt caching, batch APIs, model routing, semantic caching and output discipline, can cut a typical bill by half or more. The maths below uses one real workload throughout, so you can see exactly where the money goes. Key takeaways Prompt caching is the biggest win for repeated context: Google discounts cached input by 95% on Gemini 4 Argon, turning a $4,800 monthly input bill into $525. Batch APIs cost half the standard rate at Google and Anthropic, so anything that can wait a few hours should never run synchronously. LLM APIs charge per million tokens, and the two sides of the bill are priced very differently. Output tokens typically cost about five times input tokens: Gemini 4 Argon lists $2 per million input tokens and $10 per million output tokens through 30 November 2026, according to Google's Gemini API pricing page. Output pricing includes thinking tokens, so reasoning you never see is billed at the highest rate. The second problem is repetition. A support assistant that re-sends the same 7,500-token product manual with every question pays to read the manual ten thousand times a day. Prompt caching is the cheapest saving here because it needs no model change and no quality trade-off. When the same prefix of a prompt repeats, the provider charges a fraction of the normal input price for it. Google's implicit caching on Gemini 4 Argon discounts cached input by 95%, charging $0.10 per million tokens instead of $2, and switches on automatically for prompts of at least 4,096 tokens. On our workload, 7,500 of the 8,000 input tokens are identical every time. Cached, those cost $0.00075 per request; the 500 fresh tokens cost $0.001. Output is untouched at $1,800, so the total bill becomes $2,325, a 65% saving from a change that is mostly about prompt structure. When should you use batch APIs? Batch APIs trade latency for price: you submit a file of requests, collect the results hours later, and the provider charges half the standard rate. Google lists Gemini 4 Argon batch rates at $1 per million input tokens and $5 per million output tokens through November, and Anthropic offers the same 50% discount. On our workload, batching everything cuts input from $4,800 to $2,400 and output from $1,800 to $900, for a total of $3,300, exactly half the baseline. Batching only fits work that can wait. Nightly reports, bulk classification, evaluation runs and data enrichment are ideal; a live chat reply is not. Split traffic by deadline: anything with a service level above a few hours goes to batch by default. Model routing means sending each request to the cheapest model that can handle it, instead of sending everything to the flagship. The price gaps are enormous: Claude Haiku 5.5 costs $0.10 per million input tokens and $0.50 per million output tokens, against $2 and $10 for Gemini 4 Argon at introductory rates, according to Anthropic's and Google's pricing pages as of 24 October 2026. Semantic caching stores answers you have already given and returns them when a new question means the same thing, even if the wording differs. Where prompt caching saves you from re-reading the same documents, semantic caching saves you from re-generating the same answer. It pays off in support and FAQ workloads, where the same questions arrive in different words all day. The saving depends entirely on your repeat rate, so measure before building. Log a week of questions, embed them, cluster near-duplicates, and count the share a cache would have served. If fewer than 10% repeat, skip it. If a third repeat, a cache can remove a third of your generation bill outright. A small table keyed by embedding, with a similarity threshold around 0.9 and a time-to-live, is enough to prove the value before investing in a vector store. How do you stop paying for tokens you never needed? The fifth technique is output discipline, and it attacks the most expensive tokens on the bill. First, cap reasoning: on models with thinking levels, such as Argon's low, medium and high settings, start at the lowest level that passes your quality checks, because thinking tokens are billed as output. Second, set a real max_tokens limit and a stop sequence instead of letting the model ramble. Third, stop retrying blindly: a failed call retried three times triples the cost of one failure, so retry only on transient errors, with backoff. Structured output helps too: asking for a JSON object with exactly the fields you need produces shorter, parseable answers than a free-form essay you then summarise. On our workload, trimming the average answer from 600 tokens to 400 tokens saves $600 a month at Argon output prices, with no model change at all. What does the combined bill look like?
