Here is what I found in source/core/Ky.ts (lines 1110–1141): Every Ky request wraps the entire retry loop inside a single total-timeout Promise.race ( #timeoutPromise , defaulting to 10_000 ms ). When an upstream API returns HTTP 429 Too Many Requests with a standard Retry-After: 60 header (60 seconds), #calculateRetryDelay parses the header into 60_000 ms . Look at the guard on lines 1137–1140: // source/core/Ky.ts:1137-1140 if ( this . # remainingTimeout !== undefined && delay > this . #remainingTimeout ) { return false ; } In v2.2.0 , that check does not exist! Instead, Ky calls await delay(60_000) while #timeoutPromise has ~9,950 ms left on the clock: The caller stalls for the entire remaining 9.95 seconds doing nothing. When the timer fires, Ky aborts the sleep and throws TimeoutError — completely discarding the 429 HTTPError and its Retry-After header so caller error-handling never learns it was rate-limited.
