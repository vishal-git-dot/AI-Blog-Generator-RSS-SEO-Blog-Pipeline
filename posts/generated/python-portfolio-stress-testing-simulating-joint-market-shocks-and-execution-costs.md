# Python Portfolio Stress Testing: Simulating Joint Market Shocks and Execution Costs

## Overview

A portfolio can appear diversified under normal market conditions and still become highly exposed when several risk factors deteriorate together. For example, a digital-asset portfolio may face: Falling BTC and ETH prices. Rising implied volatility. Higher cross-asset correlation. Reduced order-book depth. Wider execution spreads. Testing these conditions independently may miss the combined effect. A more useful approach is to define coherent scenarios, apply their shocks to portfolio positions, and separately account for stressed execution costs. 1. This example deliberately excludes options and other nonlinear instruments. Those require instrument-specific valuation models. 2. Define joint market scenarios Instead of changing one asset at a time, define scenarios that describe a consistent set of market conditions. scenarios = { "moderate_stress" : { "BTC" : - 0.10 , "ETH" : - 0.15 , "execution_cost_bps" : 20 } , "severe_stress" : { "BTC" : - 0.20 , "ETH" : - 0.25 , "execution_cost_bps" : 75 } , "extreme_stress" : { "BTC" : - 0.30 , "ETH" : - 0.40 , "execution_cost_bps" : 150 } } These values are illustrative assumptions, not calibrated historical estimates or forecasts. The execution-cost assumptions are also simplified. In a production model, costs should depend on order size, market depth, spread, volatility, and execution horizon. 3. Separate market losses from execution costs The distinction matters. A portfolio may experience a substantial mark-to-market loss even if it can be liquidated efficiently. Alternatively, market losses may be relatively moderate while poor liquidity makes reducing the position expensive. These are different sources of risk. Combining them into one unexplained number makes it harder to identify which control needs improvement. A more developed framework should track: Market valuation changes. Bid-ask spread changes. Market impact. Position liquidation time. Financing and margin changes. Counterparty exposure. 5. Extend the model beyond linear assets The simple example above is not sufficient for portfolios containing options. An option's stressed value depends on more than the underlying asset's return. A fuller scenario engine should update the relevant pricing inputs, including: Underlying asset prices. Implied volatility surfaces. Interest rates and financing assumptions. Time to expiration. Relevant correlation or dependence assumptions. For sufficiently large shocks, full repricing is preferable to simply applying the current Delta. The same principle applies to portfolios with nonlinear hedges or path-dependent instruments. 6. Add reverse stress testing A further extension is to start with a predefined loss threshold. For example: LOSS_LIMIT = - 150_000 results [ "breach" ] = ( results [ "total_pnl_usd" ] < LOSS_LIMIT ) print ( results [ [ "scenario" , "total_pnl_usd" , "breach" ] ] ) This identifies which of the specified scenarios breaches the illustrative loss threshold. It is not yet a complete reverse stress test. A genuine reverse stress analysis must search for combinations of risk-factor changes that produce the specified adverse outcome, subject to documented constraints and economically meaningful assumptions. 7. From scenario results to risk controls For KAEL AI's quantitative research, the value of scenario analysis is not simply producing a larger collection of loss estimates. It is understanding which combinations of market conditions can undermine a strategy's risk assumptions and execution capabilities. A practical framework should connect the results to position limits, liquidity buffers, hedge requirements, and restrictions on additional risk. Stress testing does not guarantee that a strategy will withstand every market event. It provides a structured way to identify vulnerabilities before those conditions become operational problems. Conclusion Joint market shocks can reveal risks that isolated sensitivity tests overlook. Python provides a straightforward starting point for scenario construction and portfolio-level calculations, but realistic stress testing requires more than a few price shocks. Liquidity, nonlinear valuation, financing, model assumptions, and execution constraints must also be considered. The objective is to understand not only how much a portfolio might lose, but also whether the strategy can still operate within its risk limits when market conditions deteriorate.
