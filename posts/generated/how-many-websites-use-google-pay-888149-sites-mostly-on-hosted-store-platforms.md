# How Many Websites Use Google Pay? 888,149 Sites, Mostly on Hosted Store Platforms

## Overview

As of November 16, 2026, webatla counts 888,149 websites running Google Pay, 0.27% of the 325.8 million websites it tracks. That ranks Google Pay 142nd among the 3,083 technologies in webatla's index, or roughly one site in every 367. Four of the five sample rows on the Google Pay page answer from the same /24 block of addresses, and all five list Shopify in their stack. For anyone who writes payment code, that detail says more about how many websites use Google Pay than the headline does. A row can mean a developer loaded Google's API and wired up a payment flow. It can also mean a hosted store platform switched the button on for thousands of shops at once, and the hosting data points strongly to the second case. The live count sits on webatla's Google Pay technology page , and the long version with yearly tables is the Google Pay statistics article on the webatla blog. What lands a site in the Google Pay file The technology page is careful about its own claim. A row means the scan found the Google Pay integration in the site's markup. Read that as "the capability is wired up". It says nothing about how many shoppers tap the button, and the page states plainly that it sees the integration, not the transaction. A row can sit on a store that never took a wallet payment. Commerce platforms often inject wallet code by default, so the script can be present where the merchant never gave Google Pay a thought. A visitor may never see the button. Wallet buttons are commonly shown only when the browser, device and country support them. Code being present and a button being displayed are two separate facts. A missing row is weak evidence. A store can accept Google Pay on a hosted payment page that lives on another domain, and a scan of public pages never reaches it. One more detail for anyone matching records by name. webatla keeps Google Wallet as a separate entry with 265 sites, so the two names are never merged into one count. Each row also carries the date its technologies were last checked. On the five sample rows of the Google Pay page those dates fall between October 28 and November 13, 2026, while the file itself is dated November 16. A single row is a snapshot from its own check date. Looking for Google Pay on a single store You do not need a crawler to test one site. Google's web integration has a public, documented shape, and it leaves traces you can find in a few seconds. The technology page does not say which trace produces a webatla row, so treat the checks below as quick signals for your own review, separate from webatla's method. The first trace is Google's API script. A direct integration loads pay.js from pay.google.com . Once it runs, google.payments.api.PaymentsClient exists, and the documented sequence is to call isReadyToPay() and only then draw a button with createButton() . The second trace is a button rendered by someone else's code, such as a platform widget or a processor's client library, sometimes inside an iframe. The third is a plain accepted-payments icon in the footer, which is only a picture of the logo. Open a product page, open DevTools and paste this into the console. // Paste into the DevTools console on a product or cart page. const apiTags = [ . . . document . scripts ] . filter ( ( s ) => s . src . includes ( 'pay.google.com' ) ) console . log ( 'Google Pay API script tags:' , apiTags . length ) console . log ( 'google.payments.api loaded:' , Boolean ( window . google ? . payments ? . api ) ) const named = ( el ) => / google pay / i . test ( el . getAttribute ( 'aria-label' ) || el . getAttribute ( 'alt' ) || el . textContent ) const marks = [ . . . document . querySelectorAll ( 'svg title, img[alt], [aria-label]' ) ] . filter ( named ) console . log ( 'Icons and buttons named Google Pay:' , marks . length ) console . log ( 'iframes on the page:' , document . querySelectorAll ( 'iframe' ) . length ) The output reads like this. A script tag pointing at pay.google.com , or a loaded google.payments.api object, means someone integrated the Google Pay API on this page. Icons or buttons named Google Pay without the API usually mean a payment mark or a widget from the platform. Look at the iframe count too. A processor can draw its wallet button inside a frame, and a widget can live in a shadow root. This snippet cannot see into either from the top page. All zeros proves little. Many stores load wallet code only on the cart page, after a user action, or for supported browsers. Run the snippet on the page that matters, ideally the cart, in a browser that supports the wallet.
