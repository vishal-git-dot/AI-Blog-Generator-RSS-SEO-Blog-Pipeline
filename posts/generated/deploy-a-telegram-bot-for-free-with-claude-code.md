# Deploy a Telegram bot for free with Claude Code

## Overview

You want a Telegram bot that works all the time, not only when your laptop is on. For that you need three things: a bot token from BotFather, a public HTTPS address, so Telegram can send messages to your bot, a server that keeps the bot running. The token is easy. The other two usually mean a VPS: you rent a server, set up a web server, get a certificate, and make sure the bot restarts when it crashes. This guide skips all of that. You tell Claude Code what bot you want. It builds the bot on vbtnl and gives you a live address. VBTNL_URL is the public address of the bot. When the bot starts, it sends this address to Telegram, so you never copy a URL by hand. Webhook or polling? A bot can get messages in two ways: Polling. The bot asks Telegram again and again: "Any new messages?" Webhook. Telegram sends every new message to the bot's address. Polling is fine on your laptop. On a server, a webhook is better. The bot does nothing until a message comes, it answers faster, and it is just a normal web app. Telegram sends webhooks only to HTTPS addresses. Every vbtnl address already has HTTPS, so there is no certificate to set up. Watch out. One bot token can have only one webhook. If both the draft and production register it, the one that started last gets the messages and the other one is silent. That is why the code registers the webhook only in production. The secret token The webhook address is public. Anyone who finds it can send fake messages to your bot. Telegram has a simple fix. When you call setWebhook , you also send a secret_token . Then Telegram puts this value in the X-Telegram-Bot-Api-Secret-Token header of every request. The code checks the header and answers 403 if it is wrong. Keep this secret where you keep the bot token: in the project secrets, not in the code. Step 4. Test, then publish The draft doesn't get real messages from Telegram.
