Anthropic launches Claude Ship to automate the whole pull-request loop Anthropic released Claude Ship on November 24, a beta for Team and Enterprise plans that automates pull-request reviews, fixes and approvals on GitHub repositories. It bundles three components: Code Review, which has now reached general availability, plus PR Steward and Claude Approvals. Developers trigger the flow with the /ship command in Claude Code. — Anthropic The governance model is the part worth studying. Teams write approval policies as repository files, and those files decide what Claude is allowed to merge without asking a human. That design puts the permission boundary in version control, where it can be reviewed, diffed and audited like any other code, instead of buried in a dashboard setting. PR Steward handles the follow-up work of shepherding a change through fixes and re-reviews, and Claude Approvals executes whatever the policy file permits autonomously. Anthropic is attaching a commercial push: eligible Enterprise organizations can claim $10,000 in credits if they act by January 15, 2027. The timing reads as a response to where the coding-agent market is heading. Earlier this month Cursor's supply-chain postmortem showed how much damage a compromised dependency in an AI coding tool can do, which made trust in review automation a live concern rather than a nice-to-have. If agents now write most of the code, the review queue is the bottleneck, and whoever automates it safely owns the next layer of the developer stack. 🔗 Anthropic 3. OpenAI and Cisco open-source Shirudo, a Linux runtime that blocks exploits while patches catch up OpenAI and Cisco introduced Shirudo on November 23, an open-source runtime for Linux that protects running systems during the window between disclosure and patch deployment. It uses eBPF to deploy cryptographically signed shields that block vulnerable code paths while allowing legitimate traffic through, so teams do not have to take a service offline or wait for a vendor fix. — OpenAI The demonstration is the part that connects this week's stories. In testing, a shield generated by Codex blocked the Java4Shell exploit against a live Elasticsearch service without disrupting the service. Put it next to what else happened this month: Wiz researchers found AI teams independently surfacing HTTP/2 vulnerabilities in NGINX and F5, a security engineer used Codex to find Java4Shell itself for under $200 in compute, and Amazon's Cairn agent dug through a zero-day in MONAI Label in eleven minutes. AI has clearly moved the detection side. Shirudo targets the part that has not kept up, which is mitigation at production speed. The project ships under a BSD Clause license and is open to developers and researchers, with a technical webinar scheduled for December 15. The emerging pattern is worth naming: one agent finds the vulnerability, another agent writes the shield, and a third verifies it, while human teams keep serving traffic. Runtime protection is becoming the handoff point between machine-speed discovery and human-speed change management. 🔗 OpenAI 4. AWS gives Bedrock AgentCore a bigger, cheaper runtime for always-on agents AWS announced on November 24 a substantial upgrade to the runtime layer of Amazon Bedrock AgentCore, the managed isolation environment for running AI agents. Each session can now use up to 8 virtual CPUs and 32 GB of memory, four times the compute of the previous version, with container images up to 10 GB. AWS says the extra headroom targets workloads that previously did not fit: compiling large codebases, browser-driven workflows and local model inference. — AWS The cost side of the update is just as significant. The runtime reclaims unused memory within minutes after an agent releases it, and idle agents can scale down to zero, which AWS says cuts per-session memory consumption by up to 68 percent for multi-turn conversational agents that spend much of their life waiting on model calls, tools or human approval. A new baseline pricing mode sets a minimum memory allocation per session with the ability to burst four times above it, aimed at always-on agents that need predictable cost. FUSE-based mounts now let agents persist working files to file systems including Amazon S3, and the update is available in 19 regions, including Tokyo. The analyst caveats are fair ones. Scale-to-zero introduces wake-up latency and a governance question: a dormant agent still holds permissions, so fleets of long-lived idle agents need periodic access reviews, and a bad resume path could re-execute a payment or production change. Baseline pricing also only pays off for workloads with steady memory needs. Even with those limits, the direction is clear: the infrastructure layer is being shaped around agents that live for weeks, not requests that live for seconds. 🔗 AWS News Blog 6. Amazon's K-Hub AI gives every maintenance technician the memory of ten thousand Amazon detailed K-Hub AI, its maintenance assistant built on AWS, now active across hundreds of sites worldwide. When a conveyor stops, the agent links the reported symptoms to likely causes, the correct manufacturer's manual, the required spare part and its current stock, drawing on millions of past intervention reports from Amazon's global network. The company describes it as giving a technician in Manchester instant access to every similar repair a colleague in Nashville made three days earlier. — Amazon One feature is driving most of the adoption. Parts Visual Search, launched in August 2026, lets a technician photograph a worn or damaged component and get an AI-matched identification within seconds, matched simultaneously against Amazon part numbers, OEM references and text descriptions, along with stock status and the nearest available location. Amazon says identifying an unlabeled part once meant over 30 minutes of catalogue searching and potentially an 11-hour wait for a colleague to recognize it; it now takes under two minutes. The feature has reached 70 percent regular use with month-over-month interaction growth of 28 percent. The design detail that matters for physical AI is restraint. Amazon states that when approved sources do not contain the answer, K-Hub says so clearly rather than improvising, which is the correct behavior in an environment where a wrong answer has safety consequences. Judgment stays with the technician, who compares suggested causes against what is on the floor. As factories and warehouses fill with robots and automated equipment, the scarce resource is maintenance knowledge, and Amazon is quietly turning its own repair history into the moat. 🔗 About Amazon 7.
