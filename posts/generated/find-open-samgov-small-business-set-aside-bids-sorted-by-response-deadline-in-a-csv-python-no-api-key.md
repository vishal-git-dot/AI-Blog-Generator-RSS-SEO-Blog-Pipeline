# Find open SAM.gov small-business set-aside bids, sorted by response deadline, in a CSV (Python, no API key)

## Overview

Your business qualifies for a small-business set-aside, maybe 8(a), HUBZone, service-disabled veteran-owned (SDVOSB) or women-owned (WOSB), and you want one list of every open federal bid reserved for businesses like yours, soonest deadline first. SAM.gov publishes every active contract notice in one public CSV file that it regenerates once a day, and you don't need an API key to download it. This guide reads that file and writes the open set-aside solicitations due in the next 30 days to a CSV. The notice counts and examples in this post come from one file: https://sam.gov/api/prod/fileextractservices/v1/api/download/Contract%20Opportunities/datagov/ContractOpportunitiesFullCSV.csv?privacy=Public It was 219 MB with 72,286 notices when we ran this. It's encoded as Windows-1252 ( cp1252 ), not UTF-8, and each row carries the notice type, the set-aside code and label, the response deadline, NAICS and product/service codes, the place of performance and a link to the notice. How do I list the open set-aside bids I can respond to? The script downloads the file, keeps solicitations and combined synopsis/solicitations whose set-aside code is one of seven small-business codes, keeps the newest notice for each solicitation number, and writes those due in the next 30 days to set_aside_bids.csv . The file is sorted by posted date, newest first, so a "posted today" digest can stop early. A list of everything still open can't: 682 of the 2,657 solicitations were posted more than seven days before the run, and the oldest on 14 November 2025. Keep the newest notice per solicitation number. An amendment is posted as a new notice under the same number. Of 23,383 solicitation numbers on bid notices, 6,066 had more than one notice, 3,775 of those with different deadlines across their notices and 447 with different set-aside codes. Without collapsing them you'd get 3,292 rows instead of 2,657. Collapse first and filter by date second: done the other way round, 11 solicitations stayed on the list with an old notice's deadline, even though their newest notice had moved the deadline past the 30-day window or into the past. Bid notices only. The file also holds 11,540 award notices plus presolicitations, sources sought and special notices. Those can be worth watching, but you can't submit a bid against most of them yet. No contact columns. Each row also has a primary and a secondary point of contact, with name, email and phone. The script doesn't copy them, so the CSV holds notice data only. What should I check before I trust the list? Most notices have no set-aside code at all. 41,297 of the 72,286 rows had an empty SetASideCode and 5,864 had NONE . Filter on the codes you want, and don't read an empty code as a set-aside. Some codes are JSON lists. 201 rows, all from one department, held ["SBA"] (189) or [""] (12) in the code column with an empty label. None of them was due in our 30-day window, but a plain == "SBA" test skips them without telling you. The script unwraps the list. Sole-source codes aren't open competitions. 8AN , SDVOSBS , HZS and WOSBSS (41, 83, 18 and 19 bid notices here) are the sole-source versions of the 8(a), SDVOSB, HUBZone and WOSB codes. The script leaves them out; add them to SET_ASIDES if you want to see them. Deadlines come in four shapes. Across the file, 51,272 deadlines had a UTC offset, 11,958 were a date with no time, 702 had a time but no offset and 8,354 were empty. In our 2,657 rows, 1,787 were date only and 8 had a time but no offset. Most date-only deadlines are on combined synopsis/solicitations (11,714 of the 11,958). The script reads a date-only deadline as 23:59 US Eastern on that date and a time with no offset as US Eastern. That's our assumption, not SAM.gov's, and a rough one: only 37,601 of the 51,272 deadlines with an offset (73%) used -05:00 or -04:00 , the offsets US Eastern uses. So the CSV keeps the original text in deadline_as_posted and says which case applied in deadline_tz . Check the notice before you plan around a date-only deadline or one with no offset. Don't sort the deadline text. The offsets ranged from -10:00 to +13:00 (26 different ones), because notices are posted from many time zones, overseas places of performance included. Sorted as text, 2,580 of the 2,657 rows land in a different position from the real order. For example, 2026-11-17T10:00:00-08:00 (18:00 UTC) sorts before 2026-11-17T11:00:00-05:00 (16:00 UTC). Convert to UTC first, as the script does. Place of performance is often empty. 2,096 of the 2,657 rows had no state. If you filter by state, decide what to do with those rows instead of dropping them silently. The file is about a day behind. Ours was dated 04:30 GMT on 17 November, so notices posted or amended after that weren't in it. Check Last-Modified and the notice page on SAM.gov before you bid. It reads list-style codes such as ["SBA"] (gotcha 2) as the plain code, so they match your filter and come back as SBA ; a notice with several codes comes back as, for example, SBA,8A and matches a filter on any of them, and an empty list counts as no code. A date-only deadline comes back as the date itself (for example 2026-11-27 ) with responseDeadlineHasTime: false , and a deadline with a time comes back with responseDeadlineHasTime: true : as a UTC timestamp when SAM.gov gives an offset or the notice text states the zone, otherwise as the local time SAM.gov gave with no Z, and responseDeadlineTimeZoneBasis says which. All 8 no-offset deadlines in our 2,657 rows would come back as local times, marked unknown . The Actor doesn't sort by deadline, because date-only values and timestamps have to be converted to one form first. dueAfter keeps notices whose deadline falls on or after a date, compared by calendar date, and leaves out notices with no deadline when you set it.
