# Auditing MCP Configurations and AI Agent Rules for Security Risks

## Overview

Modern developer workflows increasingly rely on AI agent configurations and Model Context Protocol (MCP) servers. Tools like Claude Desktop, Cursor, and Windsurf execute local commands, connect to remote services, and read workspace instructions from files like .cursorrules or claude_desktop_config.json . However, these configuration files can introduce serious security vulnerabilities into your environment: Plaintext API keys and tokens committed to configuration files or exposed in local environments. Unpinned runtime commands (such as executing npx or uvx packages without fixed versions), allowing upstream package updates to execute unreviewed code on your machine. Overly broad filesystem access, such as giving an MCP server read and write permissions to root ( / ), home directories ( ~ ), or entire user profiles. Unauthenticated remote endpoints that expose local agent tooling to network manipulation. Instruction injection and hidden Unicode characters (such as zero-width spaces or bidirectional overrides) embedded within repository agent instruction files. agentconfig_audit_mcp_and_rules_scanner.py is an audit script designed to inspect MCP configuration files and agent instruction rulebooks to flag these specific security issues. Install & Usage The tool is self-contained and relies entirely on Python's standard library ( argparse , json , pathlib , re , unicodedata , dataclasses , and shlex ). You do not need to run pip install for any third-party dependencies. Installation Download the script file and save it to your workspace as agentconfig_audit_mcp_and_rules_scanner.py . Ensure you have Python 3.8 or later installed. Limitations While this tool highlights high-risk patterns, it has specific design limitations based directly on its codebase: Static Regex Heuristics: Secret detection and injection detection rely strictly on static regular expressions. A credential format not listed in SECRET_REGEXES or an obfuscated prompt injection string that avoids common phrasing will not be caught. No Dynamic Variable Resolution: The scanner checks if an environment variable starts with $ or ${...} to avoid false positives. It does not inspect whether the parent shell environment securely populates those variables. Hardcoded File Target Names: During workspace discovery, discover_agent_files() only checks for a predefined set of filenames (such as .cursorrules , agents.md , claude.md , and .rules extensions). Rules stored under custom or unexpected file extensions will be skipped unless explicitly passed as target paths. JSON-Only MCP Config Support: The MCP configuration scanner assumes valid JSON formatting. It does not parse YAML, TOML, or alternative configuration formats used by non-standard orchestrators. FAQ Does the scanner transmit any found tokens or file contents to an external server? No. The script runs entirely on your local machine using standard Python modules. It performs no network calls, uploads no telemetry, and outputs findings strictly to your local standard output stream. Why does the script flag my npx or uvx command as high severity? Commands like npx @modelcontextprotocol/server-filesystem download and run the latest published version by default. If that package is modified or compromised upstream, your agent environment executes that code automatically. The scanner requires pinning a specific version tag (e.g., npx @modelcontextprotocol/server-filesystem@0.1.0 ) to pass without a finding. Can the scanner automatically redact secrets or remove invisible characters from my files? No. The scanner is an auditing tool, not an in-place mutation tool. It reports the rule ID, offending file path, line evidence, and suggested remediation, leaving actual file modifications to the developer.
