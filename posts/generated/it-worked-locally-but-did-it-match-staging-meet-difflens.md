# It Worked Locally… But Did It Match Staging? Meet DiffLens

## Overview

DiffLens: Compare Local and Staging Web Apps with Visual, Content, and Markup Diffs Have you ever finished a UI change, opened staging, and wondered: “What exactly changed between my local build and staging?” A manual check can miss small layout shifts, changed text, or unexpected DOM updates. I built DiffLens to make those differences easier to inspect. DiffLens is a local web app that compares a local page against a staging page in three independent ways: Visual diff: Which pixels changed? Content diff: Which visible text changed? Markup diff: Which elements or attributes changed? DiffLens — Compare. Understand. Ship with confidence. The problem: a screenshot does not tell the whole story A screenshot comparison is useful, but it only answers part of the question. A button may have moved by a few pixels. A heading may have changed. A link may look identical but point to a different URL. A DOM node may have been added without an obvious visual change. These are different kinds of changes, so DiffLens treats them as separate comparison layers. 1. Visual diff DiffLens captures both pages using Chromium at a fixed 1920 × 1080 viewport, then compares the screenshots using pixelmatch . Changed pixels are highlighted over a faded local screenshot. The UI provides side-by-side, slider-overlay, and diff-only views. The comparison summary also reports the percentage of pixels that differ. Treat this as a signal for investigation rather than a pass/fail score: dynamic content, font rendering, and page movement can all affect the result. 2. Content diff The content layer compares visible page text ( innerText ) line by line using the diff library. Adjacent delete/add pairs are presented as word-level modifications. Staging is the baseline; local is the candidate: Added: Content present in local but absent from staging. Removed: Content present in staging but absent from local. Edited: Existing content whose wording has changed. 3. Markup diff The markup layer compares element snapshots matched by rendered CSS path. It reports new nodes, removed nodes, text changes, and tracked attribute changes such as href , src , alt , aria-* , and form attributes. How it works Both URLs are loaded in parallel in isolated browser contexts, so cookies and browser storage are not shared between sides. Before capture, DiffLens blocks service workers, freezes animations and transitions, waits for fonts and images, and scrolls the page to trigger lazy-loaded content. It captures visible text, element snapshots, console/network diagnostics, and screenshots. Diagnostics and comparison details A visual or content difference is easier to investigate when you can also see how each page loaded. DiffLens includes a Diagnostics view with information for both sides, including HTTP status, page title, viewport, page height, visible text size, scanned element count, links/buttons/images, capture time, and console or request errors. More than a screenshot comparison Per-side headers and cookies Headers and cookies can be configured independently for local and staging. This is useful for pages behind authentication or feature flags. Basic Auth DiffLens supports preemptive Basic Auth on each side independently. Static comparisons pass credentials to Playwright through httpCredentials . Passwords are not persisted to localStorage , sent to the server, or included in exported artifacts. The UI stores only the username for display, and the password field is cleared after the session ends. Exportable results Each comparison produces a self-contained HTML report with embedded screenshots and a JSON result. Screenshots, text snapshots, and result.json are stored under .artifacts/<id>/ ; the latest 40 runs are retained. Full-page pixel diffs on long pages can be affected by vertical layout shifts. Canvas, WebGL, and video cannot be meaningfully compared as text or DOM. Bot protection may serve different content to headless Chromium. DiffLens fetches the URLs you provide, including internal hosts. It binds to 127.0.0.1 by default. Do not expose it to an untrusted network without adding authentication and appropriate SSRF protections. Only HTTP and HTTPS URLs are accepted. What's next? The next step for DiffLens is synchronized live rendering . Instead of comparing captured screenshots, this mode will render the local and staging pages side by side in the same workspace, so you can interact with both versions while reviewing them. The planned experience will include: Side-by-side view: see the local and staging pages next to each other. Slider view: use a draggable divider to reveal either page in a shared viewing area. Synchronized interactions: click a link or navigation item in one pane and the corresponding navigation action will happen in the other pane too. This makes it easier to follow the same user journey on both versions and compare the result as you go. This will build on DiffLens's existing comparison workflow by making it easier to inspect not only what changed in a capture, but also how both versions behave during the same interaction.
