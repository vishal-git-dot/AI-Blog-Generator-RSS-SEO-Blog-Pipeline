In vanilla JavaScript, you manipulate the DOM manually — querySelector, createElement, appendChild. As apps grow, this becomes unwieldy. React's insight was that the UI should be a function of state: when state changes, React computes what changed and updates only what's necessary. No more manual DOM tracking. That's why it won. React didn't win because it's fast (Vue and Svelte are faster). It won because it made large apps tractable. When your app has 100 components, 20 shared states, and 50 user interactions, React's mental model — state flows down, events flow up — is what makes the codebase possible to reason about. UI is a function of state You don't tell React what to change — you tell it what state is, and it figures out the DOM updates. This is declarative vs imperative. Once you stop trying to "update the DOM" and start "changing state," React becomes simple. 2. Props flow down, events flow up Parent passes data to child via props. Child communicates back by calling functions the parent passed down. That's the entire data flow. No two-way binding, no global state in the component tree. 3. State lives at the closest common ancestor If two components need the same state, put it in their nearest common parent. Pass it down via props. This is "lifting state up" — and it's the standard pattern for shared state. 4. Every render is a snapshot When React re-renders, it's not "updating" — it's calling your component function again with current state and comparing the result. Understanding this makes effects, closures, and stale state make sense. 5. Effects are for external sync useEffect runs after render to sync with things outside React — APIs, subscriptions, the DOM. If you're updating state in useEffect, you probably want a derived value or event handler instead. 🎬 See it in action The classic counter — the simplest React component. State, event, render. Learning React before JavaScript The #1 reason beginners fail. If you don't understand arrow functions, destructuring, map/filter, and closures, every React tutorial becomes memorization. Complete the JavaScript track first. Mutating state directly items.push(x) or user.name = 'Bob' doesn't trigger re-renders — React compares state by reference. Fix: use setters that return new values: setItems([...items, x]) . Forgetting keys in lists Rendering an array without keys produces console warnings and buggy updates. Fix: {items.map(item => )} . Use stable IDs, not array indices. Using array indices as keys If items reorder, delete, or insert, index keys cause wrong components to keep wrong state. Fix: use a stable unique ID from your data. Generate one with crypto.randomUUID() if needed. useEffect dependency mistakes Missing dependencies cause stale closures. Extra dependencies cause infinite loops. Fix: install the eslint-plugin-react-hooks plugin — it catches both automatically. useEffect for derived state If you compute values in useEffect and store them in state, you have a bug waiting to happen. Fix: compute derived values in the render function directly. useEffect is for external sync, not for computing. Prop drilling 5 levels deep Passing props through 5 components that don't use them is a smell. Fix: use Context or component composition (pass children, not props). Calling hooks conditionally if (x) { useState(...) } breaks React — hooks must be called in the same order every render. Ship-ready. ❓ Frequently asked questions Do I need to know JavaScript before React? Yes — absolutely. React is a JavaScript library. If you don't understand functions, arrays, objects, arrow functions, and closures, learning React becomes memorization instead of understanding. Spend 2-3 months on JavaScript first. Complete the JavaScript track on this site, then come back to React. What is React? React is a JavaScript library for building user interfaces. Instead of manipulating the DOM directly, you describe what the UI should look like as a function of state, and React updates the DOM efficiently when state changes. What is JSX? JSX is a syntax extension that lets you write HTML-like code inside JavaScript. Instead of createElement('div', ...), you write ... . JSX is not valid JavaScript — it's compiled by a build tool (Babel, Vite) into React.createElement calls. What is the difference between props and state? Props are data passed from a parent component to a child — they're read-only. State is data that a component owns and can change over time. When state changes, the component re-renders. The mental model: props flow down, state lives inside a component. What is a hook in React? A hook is a function that lets a component 'hook into' React features. useState adds state to a function component. useEffect runs side effects after render. useContext reads context. useRef holds a mutable value across renders. Hooks were introduced in React 16.8 (2019) and replaced class components as the standard way to write React. What is the difference between a class component and a function component? Function components are the modern standard. They're just JavaScript functions that return JSX. Class components use ES6 classes and lifecycle methods. Function components with hooks are shorter, easier to test, and align with functional programming. Do I need a build tool to use React? Not strictly. You can use React via CDN with Babel in the browser. But for real projects, use Vite (the modern standard) or Next.js (for server-rendered apps). Vite is the easiest starting point — three commands and you're running. What should I build after this course? A to-do list (learn state + events), a weather app (learn API fetching + loading states), a movie search (learn debouncing + rendering lists), a full blog (learn routing + forms), a dashboard (learn complex state + layouts).
