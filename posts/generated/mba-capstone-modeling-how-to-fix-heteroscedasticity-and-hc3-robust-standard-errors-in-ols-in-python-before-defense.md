In MBA capstone projects, Ordinary Least Squares (OLS) regression is the default statistical tool for predicting financial metrics such as revenue, cost of goods sold, or stock volatility. However, a critical failure point occurs when the assumption of homoscedasticity is violated. Heteroscedasticity—where the variance of error terms is not constant across all levels of an independent variable—invalidates the standard errors, t-statistics, and p-values generated by standard OLS output. Many students rely on default outputs from statistical packages like SPSS or basic Python functions (e.g., statsmodels.OLS.fit() ). These tools report "naive" standard errors that assume constant variance. When this assumption is violated, which is common in financial data due to scale effects (e.g., larger firms having larger absolute sales errors), the model’s inference becomes unreliable. Professors often reject these models during defense because the confidence intervals are biased, leading to incorrect conclusions about variable significance. While some packages offer robust standard errors by default, others require explicit specification. This guide details how to detect heteroscedasticity and implement HC3 (Heteroscedasticity Consistent) robust standard errors in Python to ensure your model’s statistical validity. Step-by-Step Fix / Walkthrough The correction process involves two phases: detection and adjustment. Phase 1: Detecting Heteroscedasticity in Python First, fit the baseline OLS model. We use statsmodels because it provides direct access to residual diagnostics. import statsmodels.api as sm import pandas as pd import numpy as np # Load data data = pd . read_csv ( ' financial_data.csv ' ) # Define variables # X: Independent variables (e.g., Marketing Spend, R&D) # y: Dependent variable (e.g., Revenue) X = data [[ ' marketing_spend ' , ' rd_expense ' ]] y = data [ ' revenue ' ] # Add constant term X = sm . add_constant ( X ) # Fit baseline OLS model_ols = sm . OLS ( y , X ). fit () print ( model_ols . summary ()) To test for heteroscedasticity, use the Breusch-Pagan Test or the White Test . The Breusch-Pagan test is standard for MBA-level work. # Perform Breusch-Pagan Test # The test statistic follows a chi-square distribution bp_test = sm . stats . diagnostic . het_breuschpagan ( model_ols . resid , model_ols . model . exog ) # bp_test[0] is the LM statistic # bp_test[1] is the p-value print ( f " Breusch-Pagan LM Statistic: { bp_test [ 0 ] : . 4 f } " ) print ( f " Breusch-Pagan P-Value: { bp_test [ 1 ] : . 4 f } " ) Interpretation: If the p-value is less than 0.05, you reject the null hypothesis of homoscedasticity. In this case, standard errors are invalid, and robust standard errors are required. Phase 2: Implementing HC3 Robust Standard Errors HC3 is preferred over HC1 or HC2 in small-to-medium sample sizes because it provides a finite-sample correction that is less likely to produce negative variance estimates. It adjusts the covariance matrix of the parameter estimates using the leverage values of the observations. # Fit the model with HC3 robust covariance # cov_type='HC3' specifies the heteroscedasticity-consistent estimator model_robust = sm . OLS ( y , X ). fit ( cov_type = ' HC3 ' ) # Print summary to compare with baseline print ( model_robust . summary ()) Key Parameters Explained: cov_type='HC3' : This flag instructs statsmodels to calculate the sandwich estimator for the covariance matrix. The "3" denotes the specific correction formula: $V = (X'X)^{-1} ( \sum u_i^2 (1 - h_{ii})^{-2} x_i x_i' ) (X'X)^{-1}$, where $h_{ii}$ is the leverage of observation $i$. use_t=True : By default, statsmodels uses the t-distribution for p-values when degrees of freedom are limited. Common Pitfalls & What to Check Confusing Corrected vs. Raw Standard Errors: In statsmodels , params (coefficients) do not change with cov_type . Only bse , tvalues , and pvalues change. Ensure you are extracting the correct arrays for reporting. Small Sample Sizes: HC3 is robust, but if $N < 30$, the t-distribution approximation may still be weak. Consider using the use_t=True parameter and acknowledging small sample limitations in your discussion. Multicollinearity Interaction: Heteroscedasticity does not cause bias in coefficients, but multicollinearity does. Run the Variance Inflation Factor (VIF) test before interpreting coefficients. If VIF > 10, address multicollinearity first, as robust standard errors will not fix unstable coefficient estimates. Outliers: HC3 downweights the influence of high-leverage points (via the $1 - h_{ii}$ term), but extreme outliers can still distort results. Perform a residual plot check ( model_robust.plot_leverage ) to identify and justify the exclusion or retention of influential points. Software Default Settings: In R, lm() does not use robust SEs by default; you must use the sandwich package. In Python, statsmodels requires explicit cov_type specification. In SPSS, you must go to Analyze > Regression > Linear > Options > Statistics and check "Robust Standard Errors." Relying on default GUI outputs is a frequent cause of rejection.
