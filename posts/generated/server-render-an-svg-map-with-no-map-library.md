# Server-render an SVG map with no map library

## Overview

Showing a dot on a map usually means a vendor, an API key, and a script to load. That is a lot of machinery for a drawing. You can skip all of it. The race pages on FieldRank , a rankings site for trail runners, do: the server draws each map as SVG from free public data, and the map needs nothing else to load. The drawing is the easy part. The labels are where it gets hard, and they are what this tutorial builds up to. By the end you'll have one Node script that writes a labeled map of the Alps to an SVG file under 4 KB. Why draw it on the server A locator map has one job: show where something is. It does not need to pan, zoom, or update. Drawing it ahead of time as SVG fits that job, and it drops most of what a map usually brings with it: Nothing extra to load. The map is markup inside the HTML. No script to run, no tiles to request, and no connection to another company's servers. No layout shift. The markup carries the map's size and proportions, so the browser lays it out on the first pass and nothing moves when it appears. No JavaScript in the browser. The script runs on your server, not the page. The map shows with scripts turned off, and a crawler reading the HTML sees it too. Readable by a screen reader. Give the svg element role="img" and an aria-label that names the place. Styles like the rest of the page. Inline in your HTML, it takes CSS like any other element, so its colors can follow your dark mode. No account to manage. No API key, no usage tier, and no visitor request passing through a third party. It has costs too: No pan or zoom. It is a picture. If someone needs to move around in the map, reach for a map library. Coarse detail. The coastline file is drawn for regions and countries. It has no roads, trails, or terrain, so it cannot show a course. The work moves to your server. Projecting a coastline on every request is wasteful for a picture that never changes. Draw each map once and cache it. The date line needs extra work. Land on the far side of 180° longitude falls off the map, which matters for a pin in Fiji or far eastern Russia. I worked on FieldRank, and drawing these maps turned out to be more interesting than expected, so I'll use maps from its race pages as examples of how each step looks on a live site. Each linked page was picked because it shows the thing that step is about. Open the network tab on any of them: no tile requests and no map library. What you need Node 20 or newer. The script uses no framework. world-atlas . Coastlines from Natural Earth, a public domain map dataset. topojson-client . Unpacks that file into plain coordinates. It decodes the format and draws nothing. The world-atlas repository is archived, which for a data package means finished: coastlines don't change, and there is no code in it to go stale. Start in an empty folder and install the two packages: npm init -y npm install world-atlas topojson-client Start with a dot A map is a function that turns a latitude and a longitude into an x and a y. Start by writing that function with nothing else on the canvas. Longitude maps straight to x. Latitude goes through mercY first, which stretches it toward the poles so that shapes keep their proportions. The scale of 2300 means the 720 pixel canvas covers about 18 degrees of longitude, which is enough to show a region and its nearest cities. Draw only what is in view The picture is right and the file is wrong. Check its size: ls -l map.svg It is about 880 KB. The script projected every coastline on Earth and wrote all of it into the path, and the browser then threw away everything outside the frame. For a picture that is 720 pixels wide, that is the whole budget of a page spent on Antarctica. The fix is to cut each ring down to the frame before writing it. Add this above ringPath : const BLEED = 6 ; function clipEdge ( points , axis , limit , keepBelow ) { const inside = ( p ) => ( keepBelow ? p [ axis ] <= limit : p [ axis ] >= limit ); const out = []; points . forEach (( cur , i ) => { const prev = points [( i + points . length - 1 ) % points . length ]; if ( inside ( cur ) !== inside ( prev )) { const t = ( limit - prev [ axis ]) / ( cur [ axis ] - prev [ axis ]); out . push ([ prev [ 0 ] + t * ( cur [ 0 ] - prev [ 0 ]), prev [ 1 ] + t * ( cur [ 1 ] - prev [ 1 ]), ]); } if ( inside ( cur )) out . push ( cur ); }); return out ; } function clipRing ( points ) { let out = clipEdge ( points , 0 , - BLEED , false ); out = clipEdge ( out , 0 , W + BLEED , true ); out = clipEdge ( out , 1 , - BLEED , false ); return clipEdge ( out , 1 , H + BLEED , true ); } This is the Sutherland-Hodgman algorithm. clipEdge walks around a ring and keeps the points on the inside of one straight line. Where the ring crosses the line, it adds a new point exactly on the crossing. clipRing does that four times, once for each side of the frame. The cut is made 6 pixels outside the frame, not at it. Clipping closes each shape along the cut, and that new edge takes the coastline stroke like any other. Cut at the frame and you get a gray line down the side of the map wherever land runs off it. Cut a little outside and the false edge is hidden.
