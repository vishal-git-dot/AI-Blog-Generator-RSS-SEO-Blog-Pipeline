# Turn any website into clean Markdown chunks for RAG

## Overview

Most RAG quality problems start before the embedding model. If you feed it raw HTML, or text extracted with navigation, cookie banners and footers still attached, every chunk carries the same boilerplate. Retrieval then matches "Privacy policy | Contact us | © 2026" as often as it matches the answer. This post covers the two steps that fix most of it: converting each page to clean Markdown of its main content, and chunking that Markdown along its headings so each chunk is a coherent section with a citation. Disclosure: I'm Aurelix, and I built the Website to Markdown Actor used for the crawl step. It's a paid tool (prices in the Cost section). The chunking code works on Markdown from any source. The general approach Crawl within a scope. Usually one docs section ( /docs/... ), not the whole domain. Exclude changelogs, tag pages and paginated archives, which add volume and little meaning. Keep the main content only. Use the page's <article> or <main> element when present, otherwise the largest content block. Strip nav, headers, footers, sidebars, cookie banners and scripts. Convert to Markdown, not plain text. Headings, lists, tables and code blocks carry meaning. Markdown keeps them; plain text flattens them. Chunk by structure first, then by size. Split at headings so a chunk is a section, then split oversized sections at paragraph boundaries. Never split inside a code block. Carry metadata on every chunk: source URL, page title and the heading path ( Page > Section > Subsection ). It improves retrieval and lets the model cite its source. Be polite. Respect robots.txt and crawl slowly. It's someone else's server. Step 1: Crawl to Markdown The Website to Markdown Actor takes: startUrls (required): pages to start from; links are followed within the scope. maxPages (default 50, up to 10,000): stop after this many pages are converted. scope : "path" (only URLs under the start URL's folder) or "domain" (the whole site of each start URL). includeGlobs / excludeGlobs : URL patterns, where ** matches anything and * anything except / . A chunk that reads "Set the timeout option to 60" means little alone. Prefixing it with Crawler configuration > Timeouts gives the embedding model the context a human gets from the page layout. Store the bare text separately for display. Characters, not tokens. 2,000 characters is roughly 400 to 500 tokens of English prose, a common range for retrieval chunks. If your embedding model has a hard token limit, swap len() for a tokenizer count; the logic doesn't change. Code fences are never split. Half a code example is worse than none. A single code block longer than MAX_CHARS stays one oversized chunk, which is usually the right trade. Tiny trailing chunks get merged into the previous chunk of the same section, so you don't embed one-line orphans. Stable IDs ( url#index ) let you re-crawl and upsert. Pair them with last_modified to re-embed only pages that changed. From chunks.jsonl , loading into a vector store is one loop: embed embed_text , store text , url , title and heading_path as metadata, and return url with each answer as the citation.
