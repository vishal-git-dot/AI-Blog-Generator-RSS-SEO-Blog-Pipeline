# Keep Tenancy Out of Your Laravel App: Structuring stancl/tenancy v4 as a Module

## Overview

When you develop a multi-tenant application, it's easy for the code of your central application to get entangled with the tenant code. Or you start splitting everything into Central and Tenant folders. Models |-> Central |-> Tenant but there is a better way: modules. In this post, we will talk about how to do that. The stack I'm using: Laravel 13 stancl/tenancy v4 Pest 4 How a module is usually structured First, we need to decide on a structure. Most developers structure their modules like this: Modules/Billing/ ├── src/ │ ├── Domain/ │ ├── Application/ │ └── Http/ ├── config/ ├── database/ ├── routes/ └── tests/ I decided to structure it differently, using the structure you are already used to working with: the default Laravel structure. modules/ └── Tenancy/ ├── app/ │ ├── Http/ │ │ └── Controllers/ │ │ └── Controller.php │ ├── Models/ │ │ ├── SomeModel.php │ │ └── AnotherModel.php │ └── Providers/ │ ├── TenancyModuleServiceProvider.php │ └── TenancyServiceProvider.php ├── config/ │ └── tenancy.php ├── database/ │ ├── factories/ │ ├── migrations/ │ └── seeders/ └── routes/ └── tenant.php With this structure, you can easily reason about where to put your code. And if you use PHPStorm, you can use its scopes feature to list only the module code: The feature is located in Settings -> Appearance & Behavior -> Scopes. This way, the code of the central application won't bother you. I decided to leave the frontend code and the tests in there normal folders resources and tests . The tenancy code will never be separated from the central application, because one cannot live without the other, so I like to keep my frontend and my tests in a single place. You can still include those folders in the scope, so only the tests and resources related to Tenancy are shown. Now that the structure is ready, we need to register the module. How to register the Tenancy module The stancl/tenancy v4 package comes with a TenancyServiceProvider and a config file named tenancy.php . We will move them to modules/Tenancy/app/Providers and modules/Tenancy/config respectively. We also need to create our own service provider to register the routes, config files, and providers. Now we can move on to Composer. After making these updates, you need to register the namespaces in composer.json and run composer dump-autoload : "autoload" : { "psr-4" : { "App\\" : "app/" , "Database\\Factories\\" : "database/factories/" , "Database\\Seeders\\" : "database/seeders/" , "Modules\\Tenancy\\App\\" : "modules/Tenancy/app/" , "Modules\\Tenancy\\Database\\Factories\\" : "modules/Tenancy/database/factories/" , "Modules\\Tenancy\\Database\\Seeders\\" : "modules/Tenancy/database/seeders/" } } , Structuring the tests As I said before, I like to keep the tests in the root tests folder. An easy way to structure them is to split them like this: tests ├── Central │ ├── Browser │ ├── Feature │ └── Unit └── Tenant ├── Browser ├── Feature └── Unit Using PHPStorm's scopes feature, you can include the Tenant folder, so when we select the scope, the modules/Tenancy folder and its tests will be the only ones shown. If you decide to do this, update the test suites in the phpunit.xml file: <testsuites> <testsuite name= "Central" > <directory> tests/Central </directory> </testsuite> <testsuite name= "Tenant" > <directory> tests/Tenant </directory> </testsuite> </testsuites> <source> <include> <directory> app </directory> <directory> modules/Tenancy/app </directory> </include> </source> Making your tools aware of the module Laravel Idea If you use the Laravel Idea plugin, you can make it module-aware. In my case, I'm using PHPStorm. First, configure how you are using modules. You can find it in Languages & Frameworks -> Laravel Idea -> Module System . Configure it like below: Next, go to Languages & Frameworks -> Laravel Idea -> Code Generation -> Standard Generation . Set the "Available in modules" flag to true for all the code generation types, and include the path where you want the code to be generated. Now, just use the shortcut and you will be able to generate code really fast for the Tenancy module. When generating some code, you will be prompted to choose between generating it for the central application or for a specific module. You can also change the templates used for the generated code, which gives you a lot of freedom when it comes to customization.
