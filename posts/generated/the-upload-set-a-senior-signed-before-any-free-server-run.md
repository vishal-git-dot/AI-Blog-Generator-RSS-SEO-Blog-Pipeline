# The Upload Set a Senior Signed Before Any Free-Server Run

## Overview

This workflow starts from a pairing scenario, not from a measured production incident. In that scenario the block had forty minutes left. A webhook verifier had grown a new signature check, and the laptop suite was already busy with an unrelated package install. A free server seat sat unused. Free model access was already open in the editor. The faster path looked obvious. Upload the fixture tree, ask the model to rerun the suite, and treat a green log as the end of the hour. What the hour had to protect The diff itself was small. verify_signature had to reject a stale timestamp and a bad digest. The risk was not line count. The risk was letting a hosted run define done while fixtures still held a local capture, a clock assumption, and hostnames the team was not allowed to copy off the laptop. Published pieces on this account already covered retry budgets, replay exit codes, and path denylists. This workflow keeps a different object. It keeps a host-split manifest: which files a model may read, which tests a free server may execute, and which checks stay on the laptop even when the remote seat is idle. That split is the technical subject. Hosted capacity sits around it. Capacity does not replace the split. Questions written down before any remote command The senior required answers in the pairing notes, not in the chat window. Which paths contain tokens, customer payloads, signing keys, or internal hostnames? Which tests depend on clock, locale, DNS, or outbound network, so a different host can pass for the wrong reason? Which failures must be reproduced by a command both people can rerun after the session closes? What is the stop rule if the free server returns empty, skips the new test, or resets mid-run? Could both people rerun the claim after the chat closed, without trusting the transcript? If the answer was no, the claim did not enter the notes. The decision that stayed Three host classes. One manifest. Fail closed. local-only stays on the laptop. Keys, captures, internal hosts, and clock-bound tests live here. They never enter an upload set. server-eligible may run on the free server. Pure functions and synthetic fixtures belong here, with no outbound network and no copied captures. model-visible may appear in the editor session. This class is for the diff, public interfaces, and synthetic examples. It is a subset of server-eligible, not a third dumping ground. A file can be useful and still be local-only. Usefulness is not a transfer permit. The free server is a capacity valve for the server-eligible subset when the laptop is busy. Free model access is a drafting aid for names and comments. Neither class inherits trust from the other. The hour's rule was written in one sentence and left in the notes. Nothing remote starts until the checker accepts the upload list and both names sit beside that list. Sequence the pair followed Freeze the diff. No further product edits until the host split exists. Assign classes by hand. The model may suggest file names. Humans assign the class. Write the candidate upload list as plain text, one path per line. Run the checker. A non-zero exit stops the remote plan. Run local-only tests on the laptop and record that exit code. Only if the checker is clean, run one explicit server-eligible target on the free server. Record that exit code on a separate line. If the codes disagree on a synthetic test, treat it as a host-class bug. Do not edit the assertion until collection, skip, and dependency causes are known. Store the manifest and both codes. Do not store the model summary. The laptop code wins for local-only tests. The free server never adjudicates those. It does not scan contents for secrets. A server-eligible path can still hide a token. Content review stays human. ./fixtures/a.json and fixtures/a.json are different strings here. Do not drop this example into a production upload pipeline without path normalization. Environment parity is out of scope. Locale, clock, CPU, and network still differ. Clock-bound and network-bound tests stay local-only. This split is not a data-processing agreement. Teams that must keep customer data, regulated payloads, or signing keys off shared hosts should not treat a free seat as an approved destination.
