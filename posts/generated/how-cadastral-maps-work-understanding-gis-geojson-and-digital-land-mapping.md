# How Cadastral Maps Work: Understanding GIS, GeoJSON, and Digital Land Mapping

## Overview

Have you ever wondered how digital maps represent individual plots of land, their boundaries, neighboring properties, and geographical locations? Behind these maps is a combination of technologies such as Geographic Information Systems (GIS), spatial databases, geospatial data formats, and map-rendering engines. One interesting application of these technologies is cadastral mapping — the process of representing land parcels and their boundaries digitally. In this article, we'll explore how digital land mapping works, the technologies involved, and how developers can build their own geospatial applications. 1. What Is a Cadastral Map? A cadastral map is a geographical representation of land parcels within a defined area. Each parcel represents an individual piece of land and typically contains information such as: Parcel identification number Land boundaries Geographical coordinates Land area Associated ownership or revenue records For example, in India, agricultural land parcels are commonly identified using Khasra or Gata numbers. A village cadastral map might contain hundreds of individual land parcels, each represented by a polygon. Unlike ordinary maps that primarily display roads, buildings, and geographical features, cadastral maps focus on land parcel boundaries. 2. How GIS Makes Digital Land Mapping Possible GIS stands for Geographic Information System. It is a technology used to collect, store, process, analyze, and visualize geographical data. A GIS application can combine multiple layers of information: Layer Information Village Boundary Geographical village limits Land Parcels Individual plot boundaries Roads Road networks Water Bodies Rivers, ponds, and lakes Administrative Boundaries District and tehsil boundaries Popular GIS tools and technologies include: QGIS PostGIS GeoServer Leaflet OpenLayers MapLibre GL JS 3. Understanding GeoJSON GeoJSON is one of the most popular formats for representing geographical data on the web. It is based on JSON and supports geographical objects such as points, lines, and polygons. For example, a land parcel can be represented as a polygon: { "type" : "Feature" , "properties" : { "khasra_number" : "125" , "village" : "Example Village" , "area" : 0.25 } , "geometry" : { "type" : "Polygon" , "coordinates" : [ [ [ 83.5001 , 26.7501 ] , [ 83.5010 , 26.7501 ] , [ 83.5010 , 26.7510 ] , [ 83.5001 , 26.7510 ] , [ 83.5001 , 26.7501 ] ] ] } } Notice that the polygon contains multiple coordinate pairs. These coordinates define the geographical boundary of the land parcel. One important detail: GeoJSON coordinates generally use the WGS84 coordinate reference system (longitude, latitude), with longitude appearing first. 4. How to Store Land Parcel Data When building a large-scale land mapping application, storing geographical information efficiently becomes important. PostgreSQL with PostGIS is a popular choice. A simplified table structure could look like this: CREATE TABLE land_parcels ( id BIGSERIAL PRIMARY KEY , village_id BIGINT NOT NULL , khasra_number VARCHAR ( 50 ) , area NUMERIC ( 12 , 4 ) , boundary GEOMETRY ( MultiPolygon , 4326 ) ) ; Create a spatial index: CREATE INDEX land_parcels_boundary_idx ON land_parcels USING GIST ( boundary ) ; The spatial index makes geographical queries more efficient. For example, you can find parcels that intersect a particular geographical point: SELECT id , khasra_number , area FROM land_parcels WHERE ST_Intersects ( boundary , ST_SetSRID ( ST_Point ( 83.5005 , 26.7505 ) , 4326 ) ) ; This type of query is useful when building applications where users click on a map to identify a particular land parcel. 5. Rendering Land Parcels on a Web Map Once geographical data is stored, the next challenge is displaying it in a browser. Leaflet is a lightweight JavaScript library for interactive maps. For larger datasets, rendering every polygon simultaneously may become inefficient. Vector tiles, spatial filtering, and viewport-based data loading can help improve performance. 6. Important Challenges in Building Land Mapping Applications Building a digital cadastral mapping platform involves more than simply displaying polygons. Large Geospatial Datasets A single district may contain thousands of villages and millions of geographical coordinates. Loading the entire dataset into a browser is inefficient. Solutions include: Spatial indexing Viewport-based queries Vector tiles Data simplification Caching Coordinate Reference Systems Geographical data may come from different coordinate reference systems. Before combining datasets, developers must understand their coordinate systems and transform geometries when necessary. Accurate Land Boundaries Digitized maps do not automatically guarantee physically accurate boundaries. Data quality, survey accuracy, georeferencing, and historical records all matter. Search Performance Searching by a parcel identifier such as a Khasra number should be efficient. A practical approach is to maintain separate indexed administrative and parcel identifiers, allowing users to narrow searches by state, district, tehsil, and village before querying individual plots. 7.
