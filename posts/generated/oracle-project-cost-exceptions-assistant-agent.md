# Oracle Project Cost Exceptions Assistant Agent

## Overview

Introduction Project cost exceptions are one of those areas in Oracle Fusion Cloud Project Costing that require regular attention, particularly during month-end close. When project costs fail during import, the transactions remain unprocessed until the underlying issues are addressed. These exceptions may be caused by project configuration, missing cost rates, accounting period restrictions, or other validation failures. For project accountants, the challenge is not always correcting the transaction itself. Identifying the exceptions, understanding why they occurred, and determining which issues require attention can take considerable effort. Oracle's Project Cost Exceptions Assistant introduces a conversational approach to investigating these transactions. Instead of reviewing exceptions only through conventional application pages and predefined filters, users can retrieve, categorize, and analyze unprocessed project cost exceptions using natural-language requests. The assistant also provides possible resolution options based on the exception type, helping accountants determine the next steps. This will be released in 27A Let's explore how this capability works and its relevance to Oracle Project Costing. 1. Understanding the Project Cost Exceptions Assistant The Project Cost Exceptions Assistant is designed to help project accountants investigate unprocessed project cost transactions that have encountered errors during the Import Costs process. The assistant focuses on exception analysis rather than transaction correction. Users can request exception information using natural language, review summarized results, and investigate specific exception categories without manually examining every rejected transaction. The functionality covers four primary activities: Capability Functional Purpose Exception Search Retrieve unprocessed transactions using supported filters Exception Categorization Organize exceptions into meaningful functional categories Detailed Investigation Drill down into exception types and relevant transaction attributes Resolution Guidance Display possible corrective actions based on the exception type An important distinction is that the assistant does not automatically correct rejected transactions. It helps users understand the errors and identify possible resolutions. The actual corrective activities must still be performed through the appropriate Oracle Fusion functionality. From a functional perspective, this distinction is important because exception investigation and exception correction are separate responsibilities. 2. Why Project Cost Exceptions Require Attention Project costs can originate from multiple sources, including external applications, integrations, and other Oracle Fusion modules. During cost import, Oracle validates the incoming transaction information against applicable Project Costing rules and configurations. When a transaction fails validation, it remains unprocessed. Depending on the error, the transaction may require changes to project setup, cost rate definitions, transaction attributes, or other related information. Unresolved exceptions can affect the completeness of project cost reporting and may delay downstream financial activities. For example, transactions that have not been successfully imported into Project Costing are not available for subsequent processing in the same way as successfully imported costs. This becomes particularly relevant during period-end activities, when project accountants need to review outstanding transactions before proceeding with applicable billing, revenue, and accounting processes. The Project Cost Exceptions Assistant helps address the investigation aspect of this process by providing a consolidated view of the errors that require attention. 3. Finding Exceptions Through Natural-Language Requests One of the assistant's key capabilities is retrieving unprocessed project cost exceptions using conversational instructions. Users can search using supported transaction attributes, including: Business unit Transaction source Project Cost organization Cost type Other supported transaction attributes Multiple criteria can be used to focus the results on a particular set of transactions. This is useful for organizations where project accounting responsibilities are divided across business units, transaction sources, or project portfolios. Rather than reviewing a broad list of rejected transactions, accountants can narrow the investigation to the area they are responsible for. Understanding Search Behavior There are some important considerations when using the search functionality. By default, the assistant retrieves unprocessed project cost exceptions created within the previous 90 days . Users can specify a different period or request removal of the default date restriction. For non-date attributes, searches use case-sensitive partial matching. This means that the entered value does not always need to match the complete attribute value, but capitalization matters. For reliable results, requests should clearly identify the business object being searched. For example, a request that explicitly refers to project exceptions is more precise than a general request containing only a project identifier. Clear instructions help the assistant distinguish between requests for exception information and requests for configuration details. 4. Understanding Exception Categories Retrieving the exceptions is only the first part of the investigation. The next challenge is understanding what caused the transactions to fail. The Project Cost Exceptions Assistant organizes matching records into functional categories, making it easier to identify the nature of the outstanding issues. These categories include areas such as: Exception Category Area of Investigation Project Definition Project and task configuration or transaction eligibility Rate Definition Cost rate information required for transaction processing Accounting Period Period-related validation issues The categorization helps project accountants move from a transaction-by-transaction review to a more structured investigation. Instead of immediately opening individual records, users can first understand how many exceptions exist within each category. This provides an overview of where the errors are concentrated. Project Definition Exceptions Project Definition exceptions relate to project or task configuration conditions that prevent a transaction from being processed. These may include: Transaction dates outside the project's start and finish dates Transaction dates outside the task's permitted transaction dates Project statuses that do not allow new transactions Project-level transaction control restrictions These errors generally require the accountant to review the relevant project or task configuration and determine whether the transaction information or project setup needs attention. Rate Definition Exceptions Rate Definition exceptions relate to cost rate information required during transaction processing. For example, an imported labor cost transaction may fail when the applicable worker cost rate cannot be identified. Investigating these exceptions requires reviewing the relevant rate schedule, worker information, and transaction date. Accounting Period Exceptions Accounting Period exceptions are associated with period-related validation conditions. These require investigation of the relevant accounting period setup and transaction information. Categorizing these issues helps users identify which functional area should be reviewed before corrective action is taken. 5. Drilling Down from Categories to Exception Types The assistant supports a structured drill-down process. After retrieving the exceptions, users first receive a summary organized by exception category, including the number of matching records. They can then select a category to investigate its underlying exception types. A category can be selected by entering its name or the corresponding row number from the displayed summary. The assistant then presents the exception types associated with that category. The exception descriptions are based on the relevant error message text. An important detail is that the selected category is automatically added to the search criteria. This keeps the investigation focused on the relevant exceptions as the user moves through the results. Why This Matters Different exceptions within the same functional category may require different corrective actions. For example, a Rate Definition category may contain more than one type of rate-related error. Reviewing the exception types separately helps accountants understand whether the underlying issues are similar or require different investigation paths. This is particularly useful when multiple transactions fail for related reasons. The accountant can identify the common problem before deciding how to address the affected records. 6. Reviewing Exception Details Once a specific exception type is selected, the assistant provides a more detailed view of the matching transactions. Rather than displaying every exception as an unrelated record, it groups the results using attributes relevant to the selected exception type. For missing worker cost rate exceptions, the grouping attributes include: Attribute Investigation Relevance Worker Identifies the worker associated with the exception Rate Schedule Identifies the rate schedule involved Transaction Date Helps determine the applicable rate period This grouping makes it easier to identify transactions that may share the same underlying configuration issue. It also provides useful context for determining the next investigation step. Navigation to Unprocessed Transactions When a particular grouping contains only one matching transaction, the assistant provides a deep link to the corresponding record on the Manage Unprocessed Costs page. This allows the user to navigate directly to the relevant transaction for further review. The deep-link behavior is particularly helpful because it connects the conversational investigation with the standard Oracle Project Costing transaction management page. The assistant also displays possible resolution options for the selected exception type. These recommendations provide direction for further investigation, although they do not execute the corrective action. 7. Resolution Guidance and Functional Responsibility A useful feature of the Project Cost Exceptions Assistant is its ability to suggest possible resolutions based on the exception being investigated. However, the proposed options should be treated as guidance rather than automatic corrections. The appropriate resolution depends on the underlying business and configuration requirements. For instance, a transaction rejected because of an invalid project date may require investigation of the transaction date, the project timeline, or the applicable project setup. Changing the project configuration is not necessarily the correct response in every situation. Similarly, missing cost rate information requires reviewing the relevant rate setup and determining what information is expected for the transaction. The assistant helps identify the area requiring attention, but the accountant or functional consultant remains responsible for determining the appropriate correction. This distinction is important when evaluating the capability for production use. The assistant improves the investigation process without replacing functional validation or established financial controls. 8. Functional Scope and Current Limitations The Project Cost Exceptions Assistant has a clearly defined scope. Understanding these boundaries is important for consultants and organizations evaluating the functionality. Import Costs Exceptions Only The assistant analyzes exceptions recorded by the Import Costs process. It does not currently cover every type of exception that may occur within Oracle Project Costing. Exceptions associated with the following activities are outside its supported scope: Burdening Project cost adjustments Labor distribution Borrowed and lent processing Error Messages Only The assistant considers errors generated during cost import. Warning messages are not included in its exception analysis. No Automatic Correction Although the assistant provides possible resolution options, it cannot currently perform corrective actions. Users must investigate and address the underlying issues through the appropriate application functionality. Business Unit Data Security Access to unprocessed cost exceptions follows the existing business unit data access configuration. Users can retrieve only the records they are authorized to access. Language Support The assistant currently supports requests submitted in English. These limitations should be considered when defining the assistant's role within an organization's project accounting operations. 9. Access Requirements and Security Configuration The Project Cost Exceptions Assistant is available through Oracle AI Agent Studio, subject to the required security configuration. The Project Cost Exceptions Assistant role is needed to use the capability. Oracle provides different access configuration requirements depending on whether the user already has the seeded Project Accountant role. Users Without the Project Accountant Role For users who do not have the seeded Project Accountant role or a custom role derived from it, Oracle specifies a custom role containing the required function security, data security, and role hierarchy assignments. Consultants should verify that users have the appropriate visibility before concluding that transactions are missing from the assistant's results. Resolution Guidance Does Not Replace Validation The assistant can suggest possible corrective options, but the underlying configuration and business requirements still need to be reviewed. Corrective actions should follow the organization's established project accounting procedures. Transaction Processing Remains Separate The assistant focuses on analyzing exceptions created during Import Costs. It does not replace the standard activities required to correct rejected transactions and process them successfully.
