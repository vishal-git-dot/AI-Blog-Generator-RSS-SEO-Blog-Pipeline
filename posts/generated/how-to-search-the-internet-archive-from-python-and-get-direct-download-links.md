# How to search the Internet Archive from Python and get direct download links

## Overview

I built this actor; it's a paid tool on Apify with a free trial credit. The Internet Archive holds millions of free books, films, recordings and software, and it has public APIs. But turning "every Mark Twain audiobook, with MP3 links" into a clean table still means juggling two APIs, Solr query syntax, a 10,000-result paging limit and metadata that's sometimes a string and sometimes a list. I'm an 18-year-old engineering student, and I wrapped all of that in an actor called Internet Archive Scraper . This post shows how to call it from Python and Node, what the data looks like, and one small project: a public-domain reading list with direct EPUB links. How it works, briefly The actor calls archive.org's own search API ( advancedsearch.php ) and, if you ask for files, the metadata API ( /metadata/{identifier} ). No browser, no login. Plain-word searches are limited to title, subjects and creator by default, because archive.org's full-text search is very noisy: when I sorted "moby dick" by downloads over full text, the top hit was a 1948 film noir. With the default, the top hits are actual Moby-Dick editions. Split by year or media type. File lists add one request per item. Audiobooks can have hundreds of files, so a 300-item run with files took about 5 minutes locally at concurrency 5. The default is now 10. Metadata is whatever the uploader entered. In a 300-item test, 78% had a date, 44% a license URL and 26% a publisher. It doesn't download files , it gives you the URLs. Check each item's license before reusing anything. One oddity I hit while building it: archive.org's newer "scrape" API cached responses and returned the same results for different queries. The actor uses the older, stable search API instead. If something breaks or a field is wrong, the Issues tab on the actor page reaches me directly.
