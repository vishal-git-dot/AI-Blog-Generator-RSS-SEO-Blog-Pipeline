# The Red Pencil Workshop

## Overview

The workshop opens on a staged failure, because a visible row count teaches faster than a definition. On the projector, a fake ledger shows three captures for one invoice after a short reply suggested a three-try loop around a gateway timeout. The teaching assistant does not start a lecture. She slides a red pencil across the bench and holds the next patch until the pencil mark and the test log agree. That hour is the whole lesson. It is aimed at people who already write small Python services and who review a partner's patch before it lands. A fluent answer counts as a draft. A draft earns a mark only after a local test writes evidence a neighbor can rerun on a clean machine. The pencil is not a stand-in for taste. It is a script exit line the pair reads aloud before anyone talks about merging. If the line and the test disagree, the paragraph loses. The shop picture is a traveler card, not a courtroom. On a metal part, red pencil means a second person stood at the gauge and marked the card. The mark is worthless if the gauge never moved. Here the gauge is a unit test that counts capture attempts, and the mark is one stamped line. Eighty minutes, one process Eighty minutes is enough when the files already sit on the instructor machine. The first ten minutes replay the double charge, with the attempt list on screen, so the failure is a row count. The next fifteen minutes are local setup: a virtual environment, the modules below, and one command that prints three attempts for the bad policy. The following twenty minutes are the first exercise. Pairs write a charge function that records an invoice key before the call and refuses a second call in the same process, even when the first call raised a timeout. They are not designing a payment network. They are stopping one process from repeating a side effect whose result is unknown. Fifteen minutes go to the countercheck. A neighbor may paste a model reply into a text file, but only that neighbor runs the stamp, and the stamp does not read confidence. The last twenty minutes are a clean-directory rerun, including a cheat where someone types a passing line by hand. The neighbor deletes that file, runs the test, and makes the pencil follow the gauge. Files the room can rerun The modules are a lab design, written to be copied and executed. They are not a transcript of a timed class and they are not a measured production incident. ledger.py appends the attempt before it decides to time out. That order is the trap. Who should leave this lab on the bench This lab should not be pointed at a real charge path, a mail sender, or an inventory decrement. The in-memory set dies with the process, so two workers can still capture the same invoice. It should not be the only review on a pull request.
