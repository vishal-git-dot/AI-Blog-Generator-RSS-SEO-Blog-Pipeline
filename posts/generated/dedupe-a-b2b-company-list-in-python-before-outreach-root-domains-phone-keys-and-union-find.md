# Dedupe a B2B Company List in Python Before Outreach: Root Domains, Phone Keys and Union-Find

## Overview

A prospect list merged from several sources usually contains the same company more than once. One row comes from a directory with https://www.shreepack.co.in/contact , another from a trade portal as shreepack.co.in with a sales email, and a third with only a Gmail address and a phone number written as 098290-12345 . If you send outreach from that list, the same owner gets three messages in a day, and that is the fastest way to look like a bot. This post shows how to dedupe a company list in Python with a small, standard-library-only script that collapses those rows into one company. It keys each row on a root domain and a phone key , then merges rows that share any key using union-find, so A matches B by domain and B matches C by phone and all three end up together. I tested every block below with Python 3.14; it needs 3.9 or newer for str.removeprefix . I work on Mantis, a prospecting tool for B2B teams. Duplicate rows are the first thing I clean in any merged list, and this is the approach I would hand to a developer starting from scratch. Step 3: a phone key (not a full phone cleaner) def phone_key ( value , country = "91" ) : """'+91 98290 12345', '098290-12345', '9829012345' -> '+919829012345'.""" if not value : return None raw = value . strip ( ) digits = re . sub ( r "\D" , "" , raw ) if raw . startswith ( "+" ) or digits . startswith ( "00" ) : digits = digits . lstrip ( "0" ) # already international else : if digits . startswith ( country ) and len ( digits ) > 10 : digits = digits [ len ( country ) : ] digits = country + digits . lstrip ( "0" ) # drop trunk prefix 0 if len ( digits ) < 10 : return None return "+" + digits This is only a matching key, not a validator. It strips formatting, drops the trunk prefix 0 used for STD dialling, and prefixes India's country code 91 so +91 98290 12345 , 098290-12345 and 9829012345 produce the same key. Short strings return None so they never match anything. My first version had a bug that the tests caught: it turned the UK number +44 20 7946 0958 into +91442079460958 , because it prefixed 91 to everything. Numbers that already start with + or 00 are now left as international. If your list is mostly one country, change the country default; if it is genuinely mixed, use a proper library such as phonenumbers for the key. Because duplicates chain. Row 1 and row 2 share shreepack.co.in . Row 3 has only Gmail (ignored) and a phone number that matches row 1. A group-by on one column never joins row 3 to row 2; union-find does, because each shared key links two rows and the links are transitive. The max_rows_per_key cap is the part people skip. Some keys can be shared by many unrelated businesses: an accountant's number printed on clients' listings, a shared call centre, or an agency domain hosting many client pages. Without a cap, one such key glues dozens of companies together. In my test, seven rows sharing one number stayed seven separate groups with the default cap and collapsed into a single group when I raised it. Print the keys that hit the cap and look at them; they are usually worth a manual check. What this does not do Fuzzy names. "Shree Packaging" and "Shri Packaging" are not compared at all; they merge here only because they share keys. Add name matching only as a tie-breaker inside a city, never as a key by itself, or two different "Sharma Traders" will merge. Chains and branches. Ten branches of one brand share a domain and will merge into one row. If you sell to branches, add the city or address to the domain key. Picking the best value. merge() keeps the first non-empty value. In production, prefer the most recently verified source. FAQ Why not just use pandas drop_duplicates ? It only removes exact matches on the columns you name. The rows above are never exact matches, and it cannot chain matches across columns. Should email domains count as company keys? Yes, once free-mail providers are excluded. A sales address at the company domain can be the only link between a directory row and a portal row. Is a phone match enough on its own? Usually, for small businesses, but that is exactly why the shared-key cap exists. Review anything that hits it.
