# Turn Gmail into a Free Serverless Email API in 5 Minutes!

## Overview

Every side project or simple client build ends up needing the exact same thing: a dead-simple way to send transactional emails. Whether it is a contact form on a static site, a failure alert from a cron job, or a notification ping from a small internal tool, you almost always need an API endpoint to fire off an email. The problem is the modern email API landscape for small projects has gotten annoying: Big providers now want credit cards upfront just to touch their free tier. Setup involves domain DNS verifications, DKIM, SPF records, and waiting on sandbox approvals. You end up managing API keys, dependencies, and complex SDKs just to send 5 emails a day. If you already have a Google account, you can build and host your own secure REST email API for free in about 80 lines of Google Apps Script. No credit card, no server maintenance, and no domain DNS config required. Here is what it is, how it works, what Google gives you for free, and how to set it up. What It Is It is a lightweight Google Apps Script deployed as a serverless Web App that exposes an authenticated HTTP POST endpoint. When your backend or serverless function sends a JSON payload to the endpoint, the script validates a bearer token stored in your Google Script Properties and sends the email straight from your Gmail or Google Workspace account using Google's native MailApp service. It supports: Simple JSON over HTTP POST Token-based bearer authentication Plain text and HTML emails Custom sender display names CC, BCC, and Reply-To headers Returning your remaining daily recipient quota directly in the API response What You Get for Free Google Apps Script runs entirely on Google's infrastructure at zero cost. You do not need to supply billing details or provision a cloud instance. Google provides generous daily email sending quotas based on your account type: Account Type Daily Email Recipient Quota Personal Google Account (@gmail.com) 100 recipients / day Google Workspace (formerly G Suite) 1,500 recipients / day For a personal project, portfolio contact form, or dev monitoring script, 100 free transactional emails every single day is more than enough. If you run it on an existing Workspace account, 1,500 per day covers plenty of early-stage SaaS applications or internal company tools. Even better: because the emails are sent directly through Gmail under your authenticated Google account, inbox deliverability is solid right out of the box without configuring custom SMTP servers. Limitations and Gotchas to Keep in Mind A quick reminder on practical constraints: Security rule: Always keep your AUTH_TOKEN on a server or behind an edge function. Never put the token inside client-side JavaScript or a public repo. Anyone who gets that token can send email through your account. Attachments: This basic script handles text and HTML bodies. If you need PDF invoices or zip attachments, you would need to extend the script to accept base64-encoded file data and pass them as blobs to MailApp . HTTP Status Codes in Apps Script: Google Apps Script web apps return HTTP 200 or 302 redirects for most ContentService text outputs. The script passes error status codes in jsonResponse , but you should always inspect the success: true/false key in the returned JSON body rather than relying strictly on the HTTP status code. Bulk Marketing: Do not use this for newsletters or cold outreach. Google will throttle or flag accounts that violate standard Gmail usage policies. Keep this strictly for transactional notifications and alerts.
