# How to Loop a Video With FFmpeg (Count the Plays, Cut to an Exact Length, Check the Seam With pytest)

## Overview

To loop a video with FFmpeg, put -stream_loop N before the -i it applies to. N is the number of extra plays, so -stream_loop 3 gives you four plays, -stream_loop -1 loops forever, and you stop the infinite version with -t . That is the whole trick; the rest of this post is about the three ways it quietly goes wrong and a small pytest suite that catches them. Everything below was run on November 12, 2026 with Homebrew FFmpeg 9.0.1 on macOS against a real 10.04-second clip (720x1280, 24 fps, AAC audio): the public cat example from Voor's Bad Times AI page . Any short MP4 works the same way. The three commands Loop a fixed number of times, no re-encode: # 3 plays in total = 2 extra plays ffmpeg -stream_loop 2 -i clip.mp4 -c copy -movflags +faststart clip_x3.mp4 Loop to an exact length (re-encode so the cut lands on a frame, not on a packet): ffmpeg -stream_loop -1 -i clip.mp4 -t 30 \ -c:v libx264 -pix_fmt yuv420p -crf 20 -preset veryfast \ -c:a aac -b:a 160k -movflags +faststart clip_30s.mp4 Loop the picture under a longer soundtrack and end exactly when the soundtrack ends: # measure the track first ffprobe -v error -select_streams a:0 -show_entries stream = duration -of csv = p = 0 track.m4a # then pass that number to -t (25.000 here) ffmpeg -stream_loop -1 -i clip.mp4 -i track.m4a \ -map 0:v:0 -map 1:a:0 -t 25.000 \ -c:v libx264 -pix_fmt yuv420p -crf 20 -preset veryfast \ -c:a aac -b:a 160k -movflags +faststart looped_under_track.mp4 Gotcha 1: -stream_loop 3 is four plays The option counts repeats, not plays. On the 10.04 s clip, -stream_loop 3 -c copy produced a 40.236 s file. If you want "play it three times", pass plays - 1 . The wrapper below does that for you and refuses plays=0 . Gotcha 2: -stream_loop goes before -i It is an input option and applies only to the -i that follows it. Put it after -i clip.mp4 , right before the output name, and FFmpeg 9.0.1 refuses to run: "Option stream_loop ... cannot be applied to output url ... you are trying to apply an input option to an output file". With two inputs, only the one directly after -stream_loop loops; that is how the soundtrack command keeps the music playing once while the picture repeats. Gotcha 3: a loop restarts the clip, it does not make it seamless FFmpeg's loop is a hard cut back to frame 0. To prove the restart is exact, I decoded the frame just after the 10.04 s boundary of a 2-play file and compared it with frame 0 of the source: PSNR was inf (identical). The last frame of pass 1, compared with frame 0, scored 15.9 dB : a completely different picture. In this clip the cat ends with both paws on the lens and starts sitting back, so every loop shows a visible jump. That is not a bug to fix with flags. If you need a seamless loop, the clip itself has to end where it began (or you crossfade the tail into the head, which changes the content). Measure it before you promise "seamless".
