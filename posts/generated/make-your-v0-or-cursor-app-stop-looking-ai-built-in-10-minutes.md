# Make your v0 or Cursor app stop looking AI-built in 10 minutes

## Overview

If you've built a landing page with v0, Cursor, Lovable or Bolt, you've probably had this moment: you put it next to someone else's and it's the same page. Purple-to-blue gradient, centred headline, one font, three feature cards with an icon in a circle, a pricing table, and a "Get started" button that does nothing you can see. Nothing on that page is broken. It's the average of every landing page the model has seen, and that's what you get when you don't ask for anything specific. Visitors recognise it within seconds, though, and some of them decide the product behind it got the same amount of thought. Here are the five tells I look for and a fix for each. Every fix is a couple of minutes in a Next.js App Router project with Tailwind CSS v4. I put the result in a free starter (MIT) so you can copy single pieces or start from the whole thing: Repo: https://github.com/teodoravadani/qodesign-next-starter Live demo: https://teodoravadani.github.io/qodesign-next-starter/ The five tells A gradient where a brand colour should be. One font at one weight for everything. Everything centred. An illustration where the product should be. Buttons that don't respond. 0. Get a page to work on (1 minute) To try the fixes on a clean page: npx create-next-app@latest my-app -e https://github.com/teodoravadani/qodesign-next-starter cd my-app npm run dev Or open your own project. The steps assume Next.js 15 (App Router) and Tailwind v4, the setup where globals.css starts with @import "tailwindcss" . 1. Swap the gradient for three colours (2 minutes) Delete the bg-gradient-to-r from-purple-500 to-blue-500 (or whatever your hero has). In Tailwind v4 the palette lives in CSS, and every variable in @theme becomes a utility class: /* app/globals.css */ @theme { --color-ink : #0a0a0d ; --color-paper : #f3f1ea ; --color-volt : #c6ff3d ; } Now bg-ink , text-paper and bg-volt exist. Ink is the page, paper is the text (swap them for a light theme), and the accent goes on one or two things per screen: the main button, a status dot. Once the accent is on every element it does the gradient's job again. 2. Two fonts with some character (1 minute) Pick a display face for headings and UI and a mono for numbers and small labels. The starter uses Space Grotesk and JetBrains Mono. The font @import has to be the first line of the file: @import url("https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@400;500;600;700&family=Space+Grotesk:wght@400;500;600;700&display=swap") ; @import "tailwindcss" ; @theme { --font-sans : "Space Grotesk" , ui-sans-serif , system-ui , sans-serif ; --font-mono : "JetBrains Mono" , ui-monospace , monospace ; } One trap I hit while testing this: a project set up with shadcn init (v0 projects use shadcn) already has an @theme inline block with --font-sans: var(--font-sans) . That block wins, the variable points at itself, and the page falls back to Times New Roman. Edit the --font-sans and --font-mono lines inside that existing block instead of adding new ones. Also delete any font-family: Arial left on body by the default template, and put font-sans on <body> . Then use contrast in size and weight: a bold 7xl headline with tracking-tight leading-[1.02] , body text at text-lg and 60% opacity, mono at text-xs for the small stuff. 3. Move the hero off centre (1 minute) Centred layouts are the default because they never look broken. A left-aligned hero with a width limit on the headline looks like someone placed it: < section className = "mx-auto max-w-6xl px-5 pt-28 pb-16" > < h1 className = "max-w-3xl text-5xl leading-[1.02] font-bold tracking-tight sm:text-7xl" > Know your servers are down before your users do. </ h1 > < p className = "mt-6 max-w-xl text-lg text-white/60" > Uptime, latency and deploys on one screen. Set up in two minutes, no agent to install. </ p > </ section > Write the headline as one sentence about the visitor's problem. "Supercharge your workflow" is the copy version of the purple gradient. 4. Show the product (2 minutes) Generated heroes get a blob or a 3D shape because the model has never seen your app. You have. Screenshot your best screen at 2x and put it in a plain browser frame: import Image from ' next/image ' ; import shot from ' @/assets/dashboard.webp ' ; < div className = "mt-16 overflow-hidden rounded-2xl border border-white/10 bg-ink" > < div className = "flex items-center gap-1.5 border-b border-white/10 px-4 py-3" > < span className = "size-2.5 rounded-full bg-white/15" /> < span className = "size-2.5 rounded-full bg-white/15" /> < span className = "size-2.5 rounded-full bg-white/15" /> </ div > < Image src = { shot } alt = "The dashboard" priority sizes = "(max-width: 1200px) 100vw, 1152px" /> </ div > The static import gives next/image the width and height, so nothing shifts when it loads, and it keeps working if you deploy under a sub-path. priority is there because it's the biggest thing above the fold. No app to screenshot yet? The starter has a /dashboard route you can use as a placeholder. Swap in your real screen before you launch. 5. Make every button respond (3 minutes) People feel this one without being able to name it. Click "Start free" on most generated pages and nothing visible happens. A loading state that turns into a confirmation tells the visitor their click did something. I use the free Toast Stack component for this. It installs from a registry URL with the shadcn CLI, so the source lands in your project and you can edit it: npx shadcn@latest add https://teodoravadani.github.io/qodesign-free/r/toast-stack.json Mount the toaster once in app/layout.tsx : import { Toaster } from ' @/components/toast-stack/ToastStack ' ; // inside <body> { children } < Toaster /> Then wrap your signup call: ' use client ' ; import { toast } from ' @/components/toast-stack/ToastStack ' ; const start = () => { toast . promise ( createWorkspace (), { loading : { title : ' Creating your workspace… ' }, success : ( name ) => ({ title : ' Workspace ready ' , description : ` ${ name } is live. The first check runs in 30 s.` }), error : () => ({ title : ' That didn’t work ' , description : ' Try again in a minute. ' }), }); }; The spinner stays up for at least 600 ms so a fast request doesn't flash, then turns into a check. Hover the stack and the toasts fan out. Pricing gets the same treatment. The Pricing Switch component replaces a static three-column table with a monthly/yearly switch whose prices roll like an odometer: npx shadcn@latest add https://teodoravadani.github.io/qodesign-free/r/pricing-switch.json < PricingSwitch plans = { plans } header = { < h2 > Pay for monitors, not seats. </ h2 > } onSelect = { ( plan , yearly ) => startCheckout ( plan . id , yearly ? ' year ' : ' month ' ) } /> Its digits use Saira Condensed, so add &family=Saira+Condensed:wght@700;800 to the font import from step 2. Bonus: motion that respects people (30 seconds) If you add scroll-in animations, put them behind prefers-reduced-motion . In the starter the sections fade up with a CSS scroll timeline and no JavaScript: @media ( prefers-reduced-motion : no-preference ) { .reveal { animation : reveal-up linear both ; animation-timeline : view (); animation-range : entry 0% cover 28% ; } } @keyframes reveal-up { from { opacity : 0 ; transform : translateY ( 28px ); } to { opacity : 1 ; transform : none ; } } Add className="reveal" to a section.
