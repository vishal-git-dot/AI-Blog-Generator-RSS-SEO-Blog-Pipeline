Expert: knows where the hook sits in the input chain, and writes the state machine as a pure function. Test 2: Why is my recording's audio 40 seconds shorter than the video? ASNIPP records system audio with WASAPI loopback. The first test recording looked fine, until I played a video with long silent parts: the sound drifted further and further ahead of the picture. The cause: loopback delivers no data at all while nothing is playing. No callbacks, no zeros, nothing. If you just append whatever arrives, silence disappears from the file and everything after it slides earlier. Developer: time.sleep(1/30) in a loop. Expert: knows sleep is a request, not a guarantee, and schedules against a clock. Test 4: Why did my mic get quieter when I turned on system audio? After recording, ASNIPP mixes the system track and the mic track into the MP4 with ffmpeg. Turn on both and the voice sounded half as loud. amix divides each input by the number of inputs by default. Two tracks, so each is halved. The fix is normalize=0 , but not every ffmpeg build knows that option, so the mixer tries variants in order and moves on when one fails: variants = [ chains + [ f " [a0][a1]amix=inputs=2:duration=longest:normalize=0,apad,atrim=0: { d } [m] " ], chains + [ f " [a0][a1]amix=inputs=2:duration=longest,volume=2,apad,atrim=0: { d } [m] " ], # older builds ] for fc in variants : ok , err = run_ffmpeg ( args + [ " -filter_complex " , " ; " . join ( fc ), ...]) if ok : break Look at the tail too: apad,atrim=0:{d} . If the audio is a hair shorter than the video, ffmpeg's -shortest would cut the video . Padding the audio and then trimming to the exact video length means a short track can never shorten the video. And if ffmpeg is missing entirely? ASNIPP mixes the tracks in pure NumPy and saves a .wav next to the video, with a note saying what to install. It degrades, it doesn't crash.
