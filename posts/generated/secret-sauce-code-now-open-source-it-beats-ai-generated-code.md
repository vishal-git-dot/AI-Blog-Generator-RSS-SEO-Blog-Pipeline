# Secret sauce code now open source ( * it beats AI generated code)

## Overview

TDK CLI: How a Simple service.json Becomes a Full Local Stack Most multi-service setups still force you to maintain Docker Compose files, Tiltfiles, nginx configs, port maps, and health checks by hand. AI coding agents make the application code easy, but they are still bad at keeping the local infrastructure consistent. TDK CLI solves this by treating a tiny declarative file as the source of truth and generating everything else. The Contract This is essentially all you write for a service: { "$schema" : "https://tdk-landscape.github.io/schema.service.json" , "schemaVersion" : 1 , "appName" : "orders-api" , "appType" : "backend" , "stack" : "shop" , "port" : 4000 , "healthCheckPath" : "/health" , "dependsOn" : [] } From this single file, TDK generates Dockerfiles, live-reload rules, Traefik routes, shared Postgres wiring, health probes, and the Tilt configuration that actually runs it. The engine never parses CLI flags. Discovery never builds images. The Generation Step The real glue is the template engine ( cli/src/generator/template-engine.ts ). It reads .tdk/project.json and emits files into the gitignored .tdk/.tdk-out/ directory: Tiltfile TILT_TECH_STACK.star and TILT_RESOURCE_DEFAULTS.star spec.master .tiltignore These come from Handlebars templates. The CLI also vendors a copy of the engine and discovery code so tdk up works offline. Plan host ports (prefer 80/443/5432, fall back if busy). Ensure master configs exist (regenerate if needed). Auto-enable newly discovered stacks into the pre_alpha phase. Spawn tilt up against the generated Tiltfile. Inside Tilt the engine generates per-service .autogenerated/ files, registers builds with live-update, and starts shared infrastructure. The CLI waits for readiness and prints the real URLs. It does not deploy to staging or production. The project explicitly leaves production to Helm, Argo CD, or whatever you already use. The local environment is optimized for speed and developer experience, not for being a perfect replica of production. Getting Started npm install -g @tdk-landscape/tdk-cli-core tdk doctor tdk project --yes tdk resource orders-api --type backend --stack shop --yes tdk up shop Or clone the official starter and open it in any cloud IDE.
