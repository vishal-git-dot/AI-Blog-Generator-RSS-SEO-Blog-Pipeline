# How to Scrape Funda Property Listings in Python with Funda Scraper

## Overview

By the end of this tutorial you will have a Python script that pulls Dutch homes for sale or for rent from funda.nl into structured rows: asking price, address, living area, rooms, bedrooms, energy label, agency and photo links. Funda is a Dutch property portal, and its search pages are not friendly to a quick requests script. In my tests on 7 November 2026, plain HTTP clients got an "Access Denied" stub or a verification page instead of results. Funda Scraper ( reventadata/funda-scraper ) is the Apify Actor I built to deal with that. You send it a search, it returns one row per listing. This guide runs it from Python with the Apify API client, and the sample rows below come from a real capture of a Utrecht rental search, not from an invented example. Prerequisites You need three things: Python 3.11 or newer (the Apify client for Python 3.x requires it). A free Apify account , which you can create with an email address or a GitHub login. Your API token , from Settings > API & Integrations in Apify Console. Install the client and export the token: pip install -U "apify-client~=3.0" export APIFY_API_TOKEN = "your_apify_token_here" No scraping code is needed on your side. The Actor does the fetching. What you'll achieve You will search funda.nl for rentals in Utrecht up to 1,500 EUR per month, read the rows in Python and print a one-line summary per listing, including a price per square metre that you work out yourself from two fields. Funda lists more than homes, so a rental search also returns parking spaces and storage units. You will see how to spot them and how to filter them out. The same script works for a buyer comparing asking prices across towns, a tenant watching new rentals, or an analyst building a table of energy labels by neighbourhood. Only the input changes. Step 1: Open Funda Scraper Open the Funda Scraper page on Apify Store . The Try for free button there opens the Actor in Apify Console. This tutorial uses the API from Python, so you only need the Actor name, reventadata/funda-scraper . Step 2: Choose the search The search is described by a handful of input fields: offering : sale or rent . Anything else is refused before the run starts. areas : a list of Funda area slugs such as amsterdam or utrecht , copied from the selected_area part of a funda.nl search URL. Each area is one search, and a listing found twice is kept once. Leave the list empty and the Actor searches the whole Netherlands. objectType : empty (every type), house or apartment . sort : relevance (Funda's default) or newest . maxPrice and minPrice : in EUR, and for rentals per month. minLivingAreaM2 , maxLivingAreaM2 , minBedrooms : size filters. maxItems and maxPages : caps on rows and on pages per area. A search with a maxPrice sends the price range to Funda, so Funda does that filtering. The living-area and bedroom limits are applied by the Actor after it has read a page, so they remove rows but do not reduce the number of pages fetched. To search two towns for larger apartments for sale, the input would look like this: { "offering" : "sale" , "areas" : [ "amsterdam" , "utrecht" ] , "objectType" : "apartment" , "minLivingAreaM2" : 60 , "minBedrooms" : 2 , "maxItems" : 30 , "maxPages" : 3 } Step 3: Run it from Python This script starts the Actor, waits for it, reads the dataset and prints two lines per listing: import os from apify_client import ApifyClient # 1. Initialise the client with your token from the environment client = ApifyClient ( os . environ [ "APIFY_API_TOKEN" ] ) # 2. Describe the search: rentals in Utrecht up to 1,500 EUR a month run_input = { "offering" : "rent" , "areas" : [ "utrecht" ] , "maxPrice" : 1500 , "maxItems" : 15 , "maxPages" : 1 , } # 3. Start the Actor and wait for it to finish run = client . actor ( "reventadata/funda-scraper" ) . call ( run_input = run_input ) if run is None or run . status != "SUCCEEDED" : status = run . status if run else "unknown" raise SystemExit ( f "Run did not succeed (status: {status})." ) # 4. Read the rows from the run's default dataset items = client . dataset ( run . default_dataset_id ) . list_items ( ) . items print ( f "Retrieved {len(items)} listings.\n" ) # 5. Print two lines per listing, with a price per square metre worked out here for item in items : street = " " . join ( part for part in ( item . get ( "street" ) , item . get ( "houseNumber" ) , item . get ( "houseNumberSuffix" ) ) if part ) price , area = item . get ( "price" ) , item . get ( "livingAreaM2" ) per_m2 = f "{price / area:.1f} EUR/m2" if price and area else "no living area" print ( f "{street}, {item.get('city')} | {price} EUR/month | {area} m2 | {per_m2}" ) print ( f " {item.get('propertyType')}, bedrooms: {item.get('bedrooms')}, energy label: {item.get('energyLabel')}" ) Fetching goes through an unblocking service, one page at a time, so keep maxPages small while you test. Pro tips Filter by type early. In that capture 5 of 15 rows were parking spaces or storage. Set objectType to apartment or house to leave them out. Use newest for monitoring. sort: "newest" puts fresh listings first, which suits a schedule that checks for new homes. minPrice alone filters after the fetch. It is only sent to Funda together with maxPrice , so by itself it removes rows but does not save pages. Add includeDetails only when you need it. See Step 5: it costs one extra request per row. Compute your own ratios. There is no price-per-square-metre field. Divide price by livingAreaM2 yourself, as the script does, and skip rows where either is null . Mind the ceiling. Funda serves at most 666 pages of 15 results (9,990) for any one search. If a search is larger, the run logs a warning; narrow it with a price range, a type or a smaller area. Troubleshooting Zero rows, status SUCCEEDED. The site answered but nothing matched, or the area slug is unknown. The status message says so. Check the spelling against a funda.nl URL. Zero rows, status FAILED. A malformed slug or a maxPrice below minPrice ends the run with a message to fix the input. Pages that could not be read also fail a run that saved nothing. Fewer rows than expected. The log ends with Skipped N: reason lines for rows removed by your limits, and Pushed N row(s). . Read it with client.log(run.id).get() . Funda's terms of use restrict automated collection, so check that your use of the data complies with them and with data-protection law.
