# Docs That Expire With the Code: Binding Every Generated Claim to a Source Digest

## Overview

A generated documentation line is only as trustworthy as its provenance, and fluent prose carries no provenance at all. The workflow below forces every model-written line to cite a concrete code artifact together with that artifact's digest at draft time. When the code moves, the digest changes, the citation goes stale, and the build fails before any reviewer spends attention on the page. This is a generation-time gate rather than a review-time ceremony, and it needs two standard-library scripts and one decision table. Why Review Is the Wrong Place to Catch Drift A signoff gate answers a policy question about who approved a sentence, and it says nothing about whether the sentence is still true. Reviewers rarely reopen the source file a paragraph describes, so stale prose passes approval and then rots quietly for months. Digests invert the incentive: the doc has to prove freshness mechanically, and the human reviews only the judgement calls that code cannot settle. You do not need an LLM provider to adopt this, but if you already draft with one, the citation rules below are cheap to add. Step 1 — Build a Claim-Addressable Evidence Index The index converts your repository into a list of addressable facts, each with a stable id and a short content digest. Public function and class signatures, environment variable lookups, and CLI flags give you most of what a reference page actually asserts. Regex scanning for os.getenv and add_argument misses dynamic access such as os.environ[key] or flags built from a config file, so treat index coverage as partial and stated rather than complete. Duplicate symbol names get suffixed ids, which keeps the build green but can still make a page cite the wrong twin. Prose-heavy documents such as architecture narratives gain little here, because most of their value is judgement that no artifact can anchor. Skip this approach if a machine-readable schema already generates your reference docs, since the digests would duplicate a stronger guarantee. Skip it if your team cannot sustain a nightly rebuild, because a stale index produces confusing failures and erodes trust in the gate. Skip it as well if reviewers treat a red build as noise; a gate that everyone mutes is worse than no gate.
