# Dynamics 365 Finance OData Returns Only One Company: How to Read Them All

## Overview

A sales report built on Dynamics 365 finance and operations data can look complete and still be missing most of the business. For Supply Chain Analytics teams at Aimpex Resources Group LLC, this is a problem worth catching early, because the numbers add up but only for one legal entity. What does the problem look like? A common report: a Power BI report pulls Dynamics 365 data, but the dataAreaId column shows only one company. Adding cross-company=true seems not to help when the feed uses Implementation="2.0" . In this version, the option sits on the service root and the entity is picked in a navigation step. In reports like this, the option did not carry through: let Source = OData.Feed("https://yourenv.operations.dynamics.com/data/?cross-company=true", null, [Implementation = "2.0"]), Items = Source{[Name = "InventTableBiEntities", Signature = "table"]}[Data] in Items This version calls the entity directly, with the option on that URL: let Items = OData.Feed("https://yourenv.operations.dynamics.com/data/InventTableBiEntities?cross-company=true", null, [Implementation = "2.0"]), WithKey = Table.AddColumn(Items, "CompanyItemKey", each [dataAreaId] & "-" & [ItemId], type text) in WithKey Why does OData show one company by default? Microsoft documents this on the OData page for finance and operations apps : "By default, OData returns only data that belongs to the user's default company." To see more, "specify the ?cross-company=true query option. This option returns data from all companies that the user has access to." Two parts of that sentence matter: Default company. The filter comes from the user or service account behind the call, not from the report. Companies the user has access to. cross-company=true does not bypass security. If the service account cannot see a legal entity, that data still will not come back. The cross-company behavior article explains where the filter comes from. Each data entity has a PrimaryCompanyContext property. When it is set, the entity gets a dataAreaId field that ties each row to a company. When it is empty, the entity behaves like a shared table. Not every standard entity is built for cross-company reads. How do you ask for every company, or one other company? Put the option on the entity URL, not on the /data/ root. Microsoft's two examples use the Fleet Management sample entity: https://[baseURI]/data/FleetCustomers?cross-company=true https://[baseURI]/data/FleetCustomers?$filter=dataAreaId eq 'usrt'&cross-company=true The first returns all companies the user can see. The second reads one company that is not the user's default. In your own system, swap in your entity name and company ID. The list of public entities is at [Your organization's root URL]/data , and field names are in /data/$metadata . How do you pull it from Python? A scheduled extract for a data warehouse usually runs as an app, not a person. The service endpoints overview says OData supports OAuth 2.0 with "Service to service calls using client credentials (shared secret or certificate)." The app needs two setups: an app registration in Microsoft Entra ID, and a record under System administration > Setup > Microsoft Entra applications that maps the client ID to a service account. Microsoft suggests a dedicated service account "that has the correct permissions" rather than Admin. That service account decides which companies cross-company=true can return.
