# Getting a YouTube Transcript in Python, Including the Videos That Have No Captions

## Overview

There is a moment in almost every project that touches video when somebody says, quite reasonably, that the hard part is already done because YouTube has captions. It is a comforting thought, and for a demo it is even true. The trouble begins the following week, when the list of videos grows from five to five hundred, when a third of them turn out to have no captions at all, and when the person who asked for the transcripts mentions that they will need them as SRT files for the editor. This article walks through a small Python program that handles those cases properly. It fetches a transcript from a YouTube link, reads the timed segments, exports a subtitle file, and falls back to speech recognition when a video has no captions. I should say at the outset that I work on Transcript Dock, the API used throughout, so you may weigh my enthusiasm accordingly. Everything here runs on the free plan, which gives you fifty caption transcripts every thirty days without a card, except for the final section on AI transcription, which needs a paid plan. Why a transcript is a job and not a single request It would be convenient if a transcript arrived in the response to one HTTP call, and for videos that were fetched before, it more or less does. In general, however, the service has to resolve the link, find the right caption track, and sometimes download audio and send it to a recognition engine. Some of those steps take a fraction of a second and some take a minute. The API therefore treats every request as a job. You submit a link, you receive a job identifier, and you ask about that job until it reaches a final state. Networks fail in inconvenient ways. A request can reach the server, start a job, and then lose its response on the way back, so that your program believes nothing happened. If it simply tries again, it may start a second job and pay twice. With an idempotency key the server recognises the repeat and hands back the original job instead. Generate a fresh key for each new submission, and reuse the same key only when you are retrying that exact request. While the job is running its status is queued , processing or awaiting_provider . When it stops, the status is succeeded , failed or cancelled , and it will not change again. The billing field tells you what the job cost. A caption transcript costs one credit, and if your workspace has fetched the same video before, the API returns the stored result and marks it cached , which costs nothing. When I ran the code above against the open movie Sintel , that is exactly what came back. Those timings are what make a transcript more than a block of prose. They let you build search that jumps to the right moment, divide a long talk into chapters, or feed a language model chunks that it can cite. On Sintel the first lines print as follows. 107.25 This blade has a dark past. 111.80 It has shed much innocent blood. 118.00 You're a fool for traveling alone, so completely unprepared. Exporting a subtitle file Editors and video players rarely want JSON. They want SRT or WebVTT, and the API will produce either without charging again for the transcript. srt = requests . get ( f "{API}/transcripts/{job['result_id']}/export" , params = { "format" : "srt" } , headers = HEADERS , timeout = 30 ) open ( "sintel.srt" , "w" , encoding = "utf-8" ) . write ( srt . text ) The other formats are txt , json and vtt . The file this produced has the sequence numbers, the arrow between timings and the comma before the milliseconds that the SRT format requires, which is more than can be said for many hand rolled exporters. When a video has no captions Sooner or later you will meet a video with no caption track at all. Music videos, voiceover clips and many short social videos are the usual culprits.
