# Coordinates Before Geometry: Georeferencing, Reference Files and Unit Discipline

## Overview

Every site model agrees with itself. That is the problem. Inside each tool, geometry is consistent. The terrain is smooth, the walls are vertical, the parts snap together. Then the terrain arrives in the drawing and sits 1.4 meters above the survey. Or an asset imports at one-twelfth scale. Or a reference file attaches at a rotation nobody remembers setting. None of these failures looks like a bug, because every individual tool did exactly what it was told. What failed was the coordinate contract. Geometry is the visible part of a site model and the least interesting part to debug. Coordinates are the part that decides whether the geometry is true. This article is about the contract and the checks that keep five different tools inside it: GenAnywhere for terrain, Archshaper for base maps, MicroStation for the record, Meshy for generated objects, and CityEngine for procedural context. The Contract Is Four Numbers Georeferencing sounds like an enterprise problem. It is four numbers and a statement of intent: A coordinate reference system, named and versioned. A linear unit, stated once and enforced everywhere. A vertical datum, stated separately from the horizontal one. A local origin, with a documented offset to the project control point. The intent is the sentence that says which of these is authoritative. In a site workflow, the survey control is authoritative. Everything else is aligned to it. Tools that generate geometry from maps or prompts are convenient, but none of them outranks the survey, and the moment that hierarchy flips, the model starts lying politely. Where Terrain Enters: GenAnywhere GenAnywhere is a terrain authoring environment. You sculpt surfaces in a browser, and the mesh stays coherent while you work. That coherence is about topology, not coordinates. A sculpted pad is a valid mesh in whatever local frame the tool is using. The contract obligation is therefore simple and easy to skip: record the transform between the authored terrain and the project CRS. If the tool exports in a local frame, export the offset with it. If it exports georeferenced, verify one known point against the survey before anyone designs on the surface. The check I run is a distance test between two control points measured in the terrain and measured on the survey. If the horizontal distance differs by more than 0.02 meters over 100 meters, something is off. At that point the cause is usually units or a projection mismatch, and finding it now costs minutes instead of a redesign. Where the Base Enters: Archshaper Archshaper generates 2D base maps from open map data and terrain, layered into buildings, roads, water, trees, and contours, and exports them with a controlled origin. That origin discipline is the reason the tool is usable at all. A base map with an arbitrary origin and a random rotation is not a base map; it is a background image that happens to have line weights. Two provenance facts belong in the manifest at this stage: the date of the source data and the state of the layers at export. A base exported in March and used in September is a claim about a neighborhood that has had six months to change. A base with trees merged into buildings cannot be separated later without redoing the export. The base also sets expectations. It is measured background, not a survey. Writing that sentence down prevents the most common downstream failure in civic work, which is a planning document inheriting map data at a precision it never had. Contours are a coordinate product, not decoration. If the surface and the contours disagree, the contours are the easier one to audit. Where the Record Enters: MicroStation MicroStation is where the model becomes a document. A DGN carries a geographic coordinate system, a reference structure, levels, and a design history. Those features are the reason the record can be audited while the study files cannot. The technical contract at this stage is the reference chain. Attach the survey, the base map, and the design geometry as separate references rather than merging them. Merging flattens provenance and makes every later correction a manual redo. Keep each reference on a named level structure, and keep one reference locked as the control. Two habits matter more than the settings. First, use the coordinate readout and precision input to place design geometry relative to control, not relative to the view. Second, snapshot the revision on the day the set is issued, and put the CRS, units, and revision in the file name and the issue note. A lock chamber is a coordinate problem with water in it. The wall tolerances do not care which tool modeled them. Where Assets Enter: Meshy Meshy generates objects from text prompts or reference images. It produces meshes with material maps and exports in standard interchange formats. What it does not produce is a coordinate system, a scale guarantee, or a survey relationship. That is acceptable for site furniture and unacceptable for anything measured. The contract rule is to normalize generated assets on import: apply a known scale, place them relative to a reference object, and record the intended dimensions in the manifest. An asset that imports at 0.08 scale and gets hand-resized in the scene is an asset with no dimensions at all. The second rule is classification. Generated objects are visual artifacts, not specification items. Tag them, keep them on their own layer, and exclude them from quantities and permit documents. A bench that looks correct and cannot be ordered is a rendering, not a product. Where Context Enters: CityEngine CityEngine generates surrounding urban fabric from written rules. Parcels, streets, and massing are produced procedurally, which means the context is only as trustworthy as the rules and the parcel data behind it. Coordinates enter here in a subtle way. Procedural context usually arrives at district scale, where small errors in origin or rotation are invisible locally and significant cumulatively. A block rotated half a degree away from the street grid will still look plausible in a rendering and will fail a shadow study, a wind study, or an emergency access review. The contract obligation is to anchor the procedural scene to the same CRS and origin as the record, and to version the rules alongside the model. A generated district whose rules are lost is a backdrop. A generated district whose rules are versioned is a tested assumption. A Manifest You Can Check The contract only works if it is executable. A small JSON manifest per stage is enough: { "project" : "riverfront_market" , "crs" : "EPSG:2255" , "horizontal_unit" : "us_survey_foot" , "vertical_datum" : "NAVD88" , "local_origin" : { "easting" : 2143550.42 , "northing" : 412880.17 , "elevation" : 6.31 } , "control_points" : [ { "id" : "CP-01" , "e" : 2143601.55 , "n" : 412914.02 , "z" : 6.44 } , { "id" : "CP-02" , "e" : 2143688.10 , "n" : 412842.77 , "z" : 5.98 } ] , "stages" : [ { "tool" : "archshaper" , "artifact" : "base_v03.dxf" , "date" : "2026-03-04" , "role" : "background" } , { "tool" : "genanywhere" , "artifact" : "terrain_opt_c.glb" , "date" : "2026-03-06" , "role" : "design_surface" } , { "tool" : "microstation" , "artifact" : "record_r07.dgn" , "date" : "2026-03-19" , "role" : "record" } , { "tool" : "meshy" , "artifact" : "furniture_set_02.glb" , "date" : "2026-03-20" , "role" : "visual_artifact" } , { "tool" : "cityengine" , "artifact" : "context_rules_v04" , "date" : "2026-03-22" , "role" : "context" } ] } And a check that runs on every export: import json , math def distance ( a , b ) : return math . sqrt ( ( a [ "e" ] - b [ "e" ] ) ** 2 + ( a [ "n" ] - b [ "n" ] ) ** 2 + ( a [ "z" ] - b [ "z" ] ) ** 2 ) manifest = json . load ( open ( "manifest.json" ) ) cp1 , cp2 = manifest [ "control_points" ] baseline = distance ( cp1 , cp2 ) for stage in manifest [ "stages" ] : if "measured_baseline" not in stage : continue delta = abs ( stage [ "measured_baseline" ] - baseline ) if delta > 0.02 : raise SystemExit ( f "{stage['artifact']}: baseline drift {delta:.3f} m. " "Check units and CRS before continuing." ) The numbers are illustrative, but the shape is the point. Every artifact declares its role, and every measured artifact proves it still agrees with control. Drift becomes a failing check instead of a discovery. The Three-Number Test If a team adopts nothing else from this article, adopt the test at the door: for every new artifact entering the model, state the CRS, the unit, and the vertical datum before the geometry loads. Three numbers, spoken aloud, written in the manifest. If the three numbers do not match the contract, the file does not enter. Most site model failures are not modeling failures. They are import failures that were never checked, discovered months later by someone measuring a dimension that felt wrong. Coordinates before geometry is not a slogan about precision. It is the order in which trust has to be established for any of the geometry to mean anything.
