# Bulk WHOIS lookup in Python with RDAP: domain age, expiry, registrar and availability (no scraping, 2026)

## Overview

If you've ever tried to run WHOIS for a few hundred domains, you know the pain: every registry formats its text differently, port 43 servers throttle you, and half the fields are redacted anyway. The good news is that you don't need WHOIS any more. Generic TLD registries have been required to run RDAP (Registration Data Access Protocol) since 2019, and ICANN let them switch off the old WHOIS service in January 2025. RDAP is plain HTTPS returning JSON, with the same structure everywhere. This post builds one script that takes a messy list of domains and returns, for each one: registrar, creation date, expiry date, domain age, days until expiry, EPP status codes, nameservers, and whether the domain is unregistered. It's useful for lead qualification (older domains are usually real businesses), brand and typo-squat monitoring, expiring-domain lists, and checking your own portfolio. How RDAP lookup works Find the right server. IANA publishes a bootstrap file, data.iana.org/rdap/dns.json , that maps each TLD to its registry's RDAP base URL. Download it once per run. Ask for the domain. GET <base>/domain/example.com returns JSON. A 404 means the name isn't registered , which gives you an availability check for free. Read the fields. Dates are in events ( registration , expiration , last changed ), the registrar is the entity with the registrar role (its name is in a jCard fn field), status codes are in status , and nameservers are in nameservers[].ldhName . A few things stand out. Big brands cluster at MarkMonitor and CSC, which are corporate registrars, so a registrar column is a decent signal for "is this a large company". wikipedia.org and stackoverflow.com were both within about three months of expiry when I ran this; that's normal for domains on auto-renew, but it's exactly the window to watch if you manage domains for clients. And the made-up name came back as a clean 404, so the same script doubles as a bulk availability checker. Gotchas I hit A registry rate-limited me for almost five hours. After a handful of test runs, Nominet (the .uk registry) answered with HTTP 429 and Retry-After: 16949 . My first version politely slept on Retry-After , so the whole script just hung. Cap the wait (the script uses 10 seconds) and report the row as rate-limited instead. Also keep concurrency per registry low; the thread pool here is fine for a few hundred domains, but for thousands, group by RDAP host and throttle each one. The IANA bootstrap file is missing some big ccTLDs. .io , .co , .me and .us all run RDAP but aren't in the file, so the script adds them by hand in EXTRA . Others, like .so , .jp , .eu and .es , have no public RDAP at all, so they come back as no-rdap . For those you're back to port-43 WHOIS or the registry's website. Some ccTLDs leave fields out. .de returns status and nameservers but no dates, and .ch has no expiry date. Don't treat a blank date as an error. Send a real User-Agent. Some RDAP servers reject Python's default urllib agent, so the script sets one explicitly. The domain normalizer is naive. It keeps shop.example.com as-is instead of reducing it to example.com , and the registry will return 404 for a subdomain, which looks like "available". For real input, reduce each host to its registrable domain with the Public Suffix List (the tldextract package does this). Registrant contacts are gone. Since GDPR, almost every registry redacts the owner's name and email in RDAP, same as in WHOIS. You get the registrar and its abuse contact, not the person. Running it on a schedule or at scale The script is enough for a weekly cron job over your own domains. If you'd rather not handle the rate limits, the extra registry servers and the subdomain logic yourself, I also published this as a cloud tool: WHOIS Domain Lookup (RDAP) on Apify (disclosure: I built it). It reduces every input to its registrable domain with the Public Suffix List, throttles per registry, adds the registrar's IANA ID and abuse contact, DNSSEC, a DNS-provider guess from the nameservers, and filters like "only expiring soon" or "only available". It costs $1 per 1,000 domains looked up; failed lookups and TLDs without RDAP are free. Either way, the old WHOIS scraping era is over. RDAP gives you the same data as clean JSON, and a few dozen lines of Python are enough to use it.
