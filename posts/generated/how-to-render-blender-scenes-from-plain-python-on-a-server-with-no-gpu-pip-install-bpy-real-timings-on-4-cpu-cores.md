# How to render Blender scenes from plain Python on a server with no GPU (pip install bpy, real timings on 4 CPU cores)

## Overview

You do not need the Blender app, a desktop or a GPU to render with Blender. Since Blender is published as a Python package, pip install bpy gives you the whole thing, Cycles renderer included, as a module you import in a normal script. I used it to render a 13-second vertical video on a 4-core cloud container. Here is a minimal version you can run, and the numbers from the real job. Disclosure: I build data tools for AI agents as Fast Data on Apify ; we render short data videos from code, which is how this came up. Nothing here needs our tools; the script is in our public data-recipes repo . Install python3.13 -m venv bvenv bvenv/bin/pip install bpy # ~430 MB wheel, Blender 5.3 at the time of writing The one trap: the wheel is built for exactly one Python version. bpy 5.3 is cp313 , so it needs Python 3.13. On 3.12 pip simply finds no matching distribution, which looks like the package does not exist. What a real job cost The clip in the image above is a lot heavier than the sphere: a procedurally modelled robot, three worlds (studio with light shafts, a lake at sunset with a physical sky and fog, a rainy neon street with 30,000 rain streaks), depth of field and motion blur. Measured on 4 shared CPU cores, with another render job running on the same machine: Scene Seconds per frame at 648x1152, 12 samples Studio (dark, two spotlights, fake light shafts) 11.2 Lake (sky, water, haze volume) 13.2 Neon street (rain, many emissive signs) 12.9 316 frames total 3,880 s, about 65 minutes At 24 fps that is 13 seconds of video per hour of rendering. Quick look-dev stills at 640 px and 8 samples took 3 to 5 seconds each, which is what makes iterating from a script bearable. The settings that mattered most Setting Why Low samples (12 to 16) plus OpenImageDenoise the denoiser does the work that 200+ samples would do; the biggest single speed-up Render at 60 % and upscale with ffmpeg (lanczos + light sharpening) about 2.8x fewer pixels; on a phone screen the softness is hard to see max_bounces 6, caustics off, indirect clamp cuts fireflies and time in glossy scenes Fake volumetrics (additive emissive cones) instead of real volume scattering real volumes were about 3x slower in the studio shot One PNG per frame, skip existing files on restart a crash after 40 minutes costs one frame, not the whole run AgX view transform highlights roll off like a camera instead of clipping, for free Things that did not work well: the hand that wipes across the lens smeared at 12 samples because motion blur plus denoising averages too little information; real volume scattering was too slow for this budget; and anything that should look worn (scratches, dirt) needs texture work that is slow to do purely procedurally. When this is the right tool Batch or templated renders : product turntables, data visualisations in 3D, the same scene with different text or numbers. CI or serverless pipelines where a GPU is unavailable or expensive and you can wait an hour. Not for interactive work or long films; on 4 cores, a minute of 1080p video at decent quality is a full day of rendering. Try it The script with comments: snippets/blender_headless_render.py .
