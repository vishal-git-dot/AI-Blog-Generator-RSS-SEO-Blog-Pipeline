# Local AI Video Generation: ComfyUI and LTX-Video 2B on an RTX 3050 6GB

## Overview

Phase 00 — Building a local AI-powered video generation pipeline. 1. Introduction AI-powered video generation has evolved significantly, but running generative models locally remains challenging, especially on computers with limited hardware resources. Many demonstrations rely on high-performance GPUs with substantial VRAM or cloud-based computing platforms. This raises an interesting question: Is it possible to generate AI videos using a laptop GPU with only 6GB of VRAM? To investigate this, I started JC IA Video , a project focused on developing a local text-to-video generation pipeline. The goal is not simply to generate videos, but to understand the underlying infrastructure, identify technical limitations, and progressively build an automated solution. In this initial stage, called Phase 00 , the objective was to validate local execution of ComfyUI with the LTX-Video 2B model and produce usable MP4 files. The result was a functional proof of concept, including the resolution of a real issue involving animated WebP conversion. 2. Phase 00 Objectives The experiment was organized around five primary objectives: Configure a Python environment with NVIDIA GPU support. Run ComfyUI locally using memory optimization techniques. Load LTX-Video 2B and generate videos from text prompts. Convert generated outputs into H.264 MP4 files. Validate the resulting media files and document the findings. An important requirement was to keep inference entirely local, without relying on external inference services. 3. A Real Issue: FFmpeg and Animated WebP After generating the videos, I encountered an issue while converting the output files to MP4. The first attempt used FFmpeg directly: ffmpeg -i input.webp \ -c :v libx264 \ -pix_fmt yuv420p \ output.mp4 However, the FFmpeg version available in the environment could not correctly decode the animated WebP files produced by ComfyUI. The observed messages included: skipping unsupported chunk: ANIM skipping unsupported chunk: ANMF image data not found The conversion process failed to produce valid MP4 videos. Subsequent validation also identified invalid media containers, including the error: moov atom not found This demonstrated an important lesson: the existence of a file with an .mp4 extension does not guarantee that it contains a valid, playable video. The container structure and media metadata must be validated. The original terminal screenshots were not preserved. Therefore, the error messages recorded during the experiment are included as textual evidence. 10. The Solution: Pillow + FFmpeg To work around the decoding limitation, I separated the conversion process into two stages. First, Pillow extracts individual frames from the animated WebP file. Then, FFmpeg encodes those frames into an H.264 MP4 video. The updated pipeline became: Animated WebP | v Pillow | v Temporary PNG Frames | v FFmpeg / libx264 | v H.264 MP4 I created a Python script to automate this conversion. The initial implementation uses Image.open() to read the animated WebP frames, TemporaryDirectory() to store temporary PNG files, and subprocess.run() to execute FFmpeg. A simplified example of the frame extraction process: from PIL import Image with Image . open ( " input.webp " ) as image : for index in range ( image . n_frames ): image . seek ( index ) frame = image . convert ( " RGB " ) frame . save ( f " { index : 05 d } .png " ) The extracted frames can then be encoded using: ffmpeg \ -framerate 8 \ -i "%05d.png" \ -c :v libx264 \ -pix_fmt yuv420p \ -movflags +faststart \ output.mp4 The yuv420p pixel format improves compatibility with media players and online platforms. The +faststart option relocates MP4 metadata to support progressive playback more efficiently. The initial converter assumes a constant frame rate. Handling variable frame durations remains a potential improvement for a future version. 11. Conclusion This experiment demonstrated that short AI-generated videos can be produced locally using an RTX 3050 Laptop GPU with 6GB of VRAM, provided that the workload is configured within the available hardware constraints. It also highlighted that building a functional AI video generation pipeline involves much more than running a generative model. It requires understanding the inference environment, managing hardware resources, interpreting execution errors, processing intermediate media formats, and validating the resulting artifacts. The animated WebP conversion issue was particularly valuable: a seemingly simple failure demonstrated the importance of separating responsibilities between tools and verifying outputs rather than assuming success. Phase 00 established the technical foundation of JC IA Video. The next step is to transform this proof of concept into a reproducible and automated pipeline. 15.
