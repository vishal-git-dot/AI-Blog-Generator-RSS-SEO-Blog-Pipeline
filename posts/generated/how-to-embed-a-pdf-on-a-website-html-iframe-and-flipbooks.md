# How to Embed a PDF on a Website: HTML, iframe and Flipbooks

## Overview

To embed a PDF on a website, point an iframe at the file's URL and give it a height. Keep a separate link below it so visitors can open the document outside the embedded viewer. For a product catalog, also check the pages with small print and decide how you will replace the file when prices change. Those details usually matter more than the embed code. Disclosure: This article was prepared for WebViewPDF. The hosted example uses its public demo catalog. Embed a PDF in HTML with an iframe Upload your PDF to your website, then use its URL as the iframe source: <iframe class= "pdf-viewer" src= "/files/catalog.pdf" title= "Product catalog" loading= "lazy" ></iframe> <p> <a href= "/files/catalog.pdf" > Open the PDF separately </a> </p> Set the dimensions in CSS: .pdf-viewer { display : block ; width : 100% ; height : clamp ( 28rem , 75vh , 56rem ); border : 0 ; } Replace /files/catalog.pdf with your file's address. This relative path assumes the PDF is hosted on the same website. The title labels the frame for assistive technology. The height gives the document room to display; width: 100% fits the frame to its container. Lazy loading is useful below the fold. Remove it if the PDF is the first thing visitors should see. The browser supplies the PDF controls. Their appearance and behavior can vary, so keep the separate link even if the embed works in your browser. You can use this without a paid viewer or CMS plugin. You still need somewhere to host the file. Use object for fallback content An object element lets you put a link inside the embed as fallback HTML: <object class= "pdf-viewer" data= "/files/catalog.pdf" type= "application/pdf" aria-label= "Product catalog" > <p> The embedded preview is unavailable. <a href= "/files/catalog.pdf" > Open the PDF </a> . </p> </object> <p> <a href= "/files/catalog.pdf" > Open the PDF separately </a> </p> Use the same CSS. The link outside the object remains available if a browser fails to show the fallback properly. For an occasional brochure or form, native embedding may be all you need. A recurring catalog can need more: search across pages, reading statistics, or a new edition behind the existing link. Embed a catalog with a hosted flipbook With a hosted flipbook, the iframe points to a reader page instead of the raw PDF. The provider handles document processing and the viewer interface; you depend on its service and plan limits. When an embedded PDF does not display Blank frame First, open the PDF or reader URL in a private browser window. Check that it opens without your administrator login and does not return a 404 or an HTML error page. If it works directly but fails in the iframe, check the browser console. The embedded page may restrict framing through Content-Security-Policy: frame-ancestors or X-Frame-Options . Your own page's CSP may also block the frame origin. Follow the supported embedding configuration for the server or provider involved. Download instead of preview Inspect the response headers. Content-Disposition: attachment requests a download. Browser settings and PDF support also affect the result; changing the iframe markup may not fix it. Works on desktop, fails on mobile Some mobile browsers handle raw PDF embeds differently. Keep the separate link and test another viewer if inline reading is essential. Also distinguish a blank viewer from an unreadable document. A frame that fits the screen does not reflow a PDF. Open a page with small specifications on a real phone and check zooming, scrolling and text size. The CMS removes the code Some editors and hosting plans strip iframe or script markup. Use the platform's supported HTML or embed block, then check the saved page. Support for iframes does not necessarily include permission to run an external script. Before you put it on a client site Open the finished page while signed out. Try a desktop browser and a real phone, follow a link inside the document, and check keyboard navigation and the separate PDF link. For catalogs, search for an actual product name or part number. If the document will be updated regularly, replace it once and reopen the original page. That is the easiest time to catch a workflow that generates a new URL for every edition. Embedding is not copy protection: hiding a download button does not secure a public PDF. It also does not put the PDF's text into the surrounding HTML. Keep essential product descriptions and navigation on the webpage when readers need them there.
