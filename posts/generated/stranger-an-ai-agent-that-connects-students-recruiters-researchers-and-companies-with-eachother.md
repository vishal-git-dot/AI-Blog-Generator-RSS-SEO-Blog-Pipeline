# 👻 STRANGER: An AI Agent That Connects Students, Recruiters, Researchers, and Companies with Eachother

## Overview

This is a submission for the Hacktoberfest Open-Source AI Challenge Week 4: Ghost in the Machine 👻 STRANGER — The Ghost in the Network That Finds Your Missing Connection Everyone is someone's missing connection. What if AI could find it? What I Built In a world with billions of people, finding the right person can still be surprisingly difficult. A student needs a hackathon teammate. A researcher needs an assistant. A startup founder needs a technical partner. A recruiter needs the right candidate. The people we need might already exist somewhere in our networks, but their skills, interests, and opportunities remain invisible to us. That's the problem that inspired STRANGER , an AI-powered human discovery and opportunity-matching agent built using Fetch.ai's Agentverse, ASI:One, and the open-source uAgents framework. How I interpreted "Ghost in the Machine" I imagined a digital ghost moving through a network of disconnected portfolios, discovering meaningful connections that people might otherwise overlook. Instead of haunting machines, STRANGER explores the information people voluntarily share to discover potential collaborators, mentors, researchers, recruiters, and teammates. The Halloween theme also inspired the concept of personalized, spooky-themed portfolio illustrations. How STRANGER works 1. Adaptive onboarding STRANGER is designed to collect meaningful user information through just two or three questions. It focuses on: Skills and experience Education and achievements Projects and interests Goals and career aspirations Problem-solving approaches Availability and collaboration preferences 2. Intelligent portfolios The agent organizes collected information into structured portfolios, including a short summary of each user's approach to problem-solving. 3. Opportunity discovery STRANGER recommends five to seven personalized directions, such as: Hackathon teammates Research collaborations Internships and employment Startup partnerships Technical mentorship Open-source collaborations Skill-exchange opportunities 4. Compatibility matching The matching engine is designed to compare profiles according to technical requirements, relevant experience, goals, availability, and complementary skills. It uses a transparent 0–100 scoring rubric rather than treating AI-generated percentages as objective probabilities. 5. Shared profile network STRANGER's architecture separates fictional demonstration profiles from real user profiles. The demo dataset is intended to cover four groups: students, recruiters, companies, and researchers. Real-user discovery requires explicit consent. Synthetic profiles must always be identified as demonstrations. Demo STRANGER is hosted on Fetch.ai Agentverse and is discoverable through ASI:One. It could understand a user's profile and offer useful advice, but it sometimes continued asking questions even after enough information was available. That revealed an important engineering lesson: An intelligent response is not the same as an intelligent workflow. To address this, I began separating AI reasoning from deterministic execution. Python manages explicit workflow states, question limits, storage operations, and compatibility calculations. ASI-1 handles tasks that benefit from language understanding and generation. This separation also helps reduce model-token consumption on the Agentverse Basic Plan. Why Does Open Innovation Matter? Open innovation matters because autonomous agents should be understandable, extensible, and interoperable. The open-source uAgents framework allows developers to inspect communication patterns, implement custom protocols, and build agents without depending entirely on a proprietary visual builder. For STRANGER, that means I can customize: How agents communicate How interviews progress How user information is structured How matching scores are calculated How profiles are stored and retrieved How external capabilities can be integrated The project uses ASI-1 as a hosted reasoning model, so it is not a fully open-weight AI application. However, its agent framework, deterministic matching logic, and workflow implementation demonstrate how open-source tooling can support an extensible agent-based system. The longer-term goal is a network of independently useful agents that can collaborate through shared protocols. My Agent Session My development journey involved generating the initial STRANGER agent, testing it through ASI:One, inspecting its Python source, and iteratively improving its onboarding and matching architecture. Several early tests exposed issues involving repeated questions, missing persistent profiles, and model-token limits.
