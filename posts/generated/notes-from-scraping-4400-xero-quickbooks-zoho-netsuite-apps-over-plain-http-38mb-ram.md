# Notes from scraping 4,400+ Xero, QuickBooks, Zoho & NetSuite apps over plain HTTP (38MB RAM)

## Overview

Test run qUI9gTtRIHTWhqEbR on our new Oracle NetSuite SuiteApp actor finished today in 3 seconds and peaked at 38.1 MB of RAM (30.5 MB average). No Playwright, no Puppeteer, no residential proxy rotation. I've spent the past few days writing HTTP-only extractors for four accounting and ERP app directories: Xero (570+ apps), QuickBooks (660+ US listings, 6,400+ across all locales), Zoho Marketplace (2,500+ extensions), and Oracle NetSuite's suiteapp.com (724 SuiteApps, 3,548 reviews). My main goal was keeping Apify compute around $0.02 per 1,000 records, which basically rules out headless Chrome from the start. Along the way I kept notes on how each store structures its backend responses and how user complaints change once you move from small-business accounting into ERP. How the four directories serve listing data None of the four required executing JavaScript to get vendor data or reviews, though each one had at least one weird serialization quirk. Xero ( apps.xero.com ) embeds <script id="mp-redux-state"> in the SSR document. You get the 1-to-5 star counts and partner links on the first GET request. QuickBooks ( apps.intuit.com ) separates the two: listing metadata and Intuit AQI scores come from appcardservice.api.intuit.com/v3/appcards/shortname (authenticated with a static public Intuit_APIKey header from their frontend bundle), and paginated reviews live on a separate GraphQL endpoint. Zoho ( marketplace.zoho.com ) exposes /getdata for pagination and /getrating?extensionId=... for reviews, but the best vendor fields sit inside the HTML of each detail page as var installURLObj = {...}.extensionDetails.installUrlObj; . Because of that trailing property access at the end of the object literal, you can't regex-capture to the semicolon and call JSON.parse directly (we had to write a tiny balanced-brace scanner that ignores braces inside quoted strings). Once parsed, partnerDetails includes supportEmail , companyEmail , phone numbers, and office street addresses. NetSuite ( suiteapp.com ) returns 2,847 bytes of empty HTML on / with <div id="content"></div> and two deferred bundles. Grepping b54ed0eff50c485d1f69.app.js showed it runs on NetSuite's own SuiteCommerce ShopFlow backend under company ID 3857091 : const detailUrl = `https://www.suiteapp.com/api/items?c=3857091&n=2&include=facets&fieldset=detail&url=${slug}` ; const reviewsUrl = `https://www.suiteapp.com/shopflow-1-03-0/services/product-reviews.ss` + `?c=3857091&order=rating%3AASC&itemid=${internalId}&limit=25&page=1` ; Two NetSuite quirks worth noting if you ever touch SuiteCommerce APIs: empty string fields on /api/items frequently come back as literal "&nbsp;" instead of "" or null , and custitem_ns_pr_rating_by_rate is a JSON-encoded string ( "{\"1\":\"1\",\"4\":\"1\",\"5\":\"33\"}" ) nested inside the outer JSON response. On the bright side, detail exposes boolean flags for the exact NetSuite integration surface ( SuiteScript 2.x , SuiteScript 1.0 , SuiteTalk REST , SuiteTalk SOAP , SuiteBundler , SuiteAnalytics , SuiteApp Control Center ), and product-reviews.ss accepts order=rating:ASC so 1-star reviews come back on page 1. 1-star reviews on SMB tools vs. NetSuite ERP Comparing low-star reviews across the four datasets, the reasons customers leave angry feedback change pretty drastically between SMB bookkeeping apps and NetSuite. On Xero, QuickBooks, and Zoho Books, 1-to-3 star reviews are mostly immediate operational bugs: Duplicate invoice or contact syncs messing up reconciliation. OAuth tokens dropping after a bank feed update. Unexpected tier changes or per-seat charges on monthly renewals. On suiteapp.com , almost nobody complains about a $20/month seat fee. The 1-star reviews are mostly about botched implementations and multi-week support silences. For example, item 20309 has 33 five-star ratings and a 1-star review from a finance lead describing go-live dates pushed back by weeks over an incorrect start date, followed by minor and major issues needing repeated escalation while finance operations sat on hold. For anyone selling ERP implementation help, middleware, or RevOps tooling, that kind of implementation_delay complaint is a much stronger buying signal than a generic software directory scrape.
