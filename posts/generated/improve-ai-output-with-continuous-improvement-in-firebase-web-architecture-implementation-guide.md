How It Works: Technical Breakdown & Implementation Getting better outputs from AI can be tough without any intervention. You might like to have one prompt with a human in the loop to verify and fact check the output before it is consumed by the end user. Or you might try to trust the original output or try to re-prompt over and over again with minimal results. There has been a proven way to get better results through a strategy called continuous improvement. Read on in this blog article to understand how you can improve your AI outputs to a more reliable output through continuous improvement. What is continuous improvement? Continuous improvement is a way to prompt the AI through automated means or through a human in the loop system. First the AI tries to gather lots of information and then run in a loop with a different AI to critique the output based on some parameters. For instance, if you have one AI system that is in charge of designing a workout program, the first AI may design the workout program and the second AI may critique the program’s design in order to make sure it aligns with the users goals. Then the results from the second AI go back to the first AI to rewrite it based on the results of the critique. Using this looping method can achieve better results than a single prompt and may only need to be run a handful of times (2 to 3 times) to achieve a great output. Using a LoopAgent for continuous improvement To demonstrate how to achieve continuous improvement, we are going to use the ADK as an example. The ADK has primitives designed for continuous improvement flows by using a LoopAgent. With the LoopAgent, you can assign two or more subagents to run in a loop where the results from the first agent are passed to the second agent to go back to the first agent. The tradeoff with continuous improvement Using continuous improvement may not be the best choice for all situations. Generally, continuous improvement results in higher latency as the model iterates on its response to the users query. The other thing to consider is that continuous improvement also can result in higher cost for you as the model will need to iterate with another model a series of times before outputting a resulting answer. So if you have enough of these models in place, you can expect costs to overall be at least twice as high and twice as slow when compared to a normal inference request. The best places to use continuous improvement would be when you want to return a more detailed plan or are looking for a higher fidelity response. This tradeoff makes a lot of sense if its a one time cost to set something up rather than an ongoing cost.
