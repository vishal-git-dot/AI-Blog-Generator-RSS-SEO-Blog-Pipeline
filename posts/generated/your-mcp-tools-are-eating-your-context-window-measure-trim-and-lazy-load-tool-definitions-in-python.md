# Your MCP Tools Are Eating Your Context Window: Measure, Trim and Lazy-Load Tool Definitions in Python

## Overview

Tuần trước mình debug một agent nội bộ: model chọn sai tool liên tục, response chậm, bill API tăng gần gấp đôi so với tháng trước. Code agent không đổi gì, prompt cũng không đổi. Hóa ra team vừa cắm thêm 3 MCP server (GitHub, Postgres, Jira), tổng cộng hơn 90 tool. Request nào cũng phải gửi kèm toàn bộ định nghĩa tool, trước khi user kịp gõ chữ nào đã mất khoảng 38.000 token . Bài này chia sẻ cách mình đo chi phí đó, cắt gọn schema và chuyển sang lazy-load tool, để agent vừa rẻ hơn vừa chọn tool chính xác hơn. Vì sao MCP tool lại tốn context đến vậy Khi agent kết nối tới một MCP server, client gọi tools/list và nhận về danh sách tool, mỗi tool gồm name , description và inputSchema (JSON Schema). Phần lớn framework đưa toàn bộ danh sách này vào mọi request gửi tới LLM. Hậu quả: Chi phí cố định cho mỗi request : 90 tool × ~400 token mỗi tool = 36k token, kể cả khi user chỉ hỏi chào buổi sáng. Model chọn tool kém đi : càng nhiều tool trùng ý nghĩa ( search_issues , search_code , search_jira ...) thì model càng dễ chọn nhầm.
