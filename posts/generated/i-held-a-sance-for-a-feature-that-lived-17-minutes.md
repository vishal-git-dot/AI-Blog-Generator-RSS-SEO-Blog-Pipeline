# I held a séance for a feature that lived 17 minutes

## Overview

This is a submission for the Hacktoberfest Open-Source AI Challenge Week 4: Ghost in the Machine What I Built On 30 September, at 15:07:58, I gave my Android app TapOff a new trick: turn the phone on its side, tap the camera hole, and the brightness and volume sliders open. At 15:25:05 I deleted it. Seventeen minutes and seven seconds. About the camera tap, the commit that killed it says only "Removed the lock-screen double-tap switch and the landscape camera tap, with their code". The rest of the story is in the code that died. One comment in it explains the whole thing: in portrait, Android's status bar sits over the camera and takes every tap there. So the trick only ever worked sideways, and I asked for it to go. Every project has a graveyard like this, and nobody visits it. So for Día de los Muertos I built Exhume : a medium that runs on my laptop, digs up the dead, and lets me ask them what happened. Exhume knows three graveyards: Code: files and functions deleted from a git repo, read from its history. Websites: dead sites, read back from the Wayback Machine. My demo is Orkut. Apps: Mac apps I stopped opening, from the last-opened date macOS keeps. For each one it does the same three things: Finds the dead and collects the evidence: commits, dates, authors, archived pages. Each piece gets an ID (E1, E2, …). The facts (when it was born, when it died, who made it, how long it lived) are worked out by code, not by the model. Writes a tombstone: a cause of death and an epitaph, written by Gemma from that evidence only. Holds a séance: you ask questions, and every answer cites the evidence it rests on. Under each answer Exhume prints the sentence from that evidence that backs it up, so you can check it yourself. If the evidence doesn't say, the answer is "The spirits are silent." Code: one Python file, exhume.py , 723 lines, standard library only. It calls git, curl and macOS's mdls . No frameworks, nothing to pip install . Code graveyard: git log -M --diff-filter=D finds deleted files that never came back. For functions, Exhume walks the whole history ( git log -p -M --unified=0 ) and matches definition lines in common languages. That's a heuristic, not a parser. Renamed files don't count, and neither does a function that comes back in the same place under a new name. Binary files are skipped, and --skip GLOB ignores generated folders. On TapOff it found 8 graves. Website graveyard: the Wayback Machine's CDX index lists the saved copies of the home page, and Exhume reads four of them, spread across the years; --page adds snapshots you name. For Orkut that's 8 pages: four home pages (2003, 2008, 2023, 2026) plus four I picked (Google's June 2014 goodbye post, the archive notice, the "Preserving Orkut's history" post and the founder's 2016 page). Pages are cached on disk, so once find has run, tombstones and séances work offline. Apps graveyard: mdls reads kMDItemLastUsedDate for each app in /Applications . Apps macOS has no record of opening are left out unless you ask for them with --unrecorded . Apps only, never documents. Keeping Gemma honest: Gemma never supplies a date, a commit or a name. Code gives it the evidence as a numbered list in the prompt. Gemma must answer in JSON that matches a schema (Ollama's format ). Its cites list is an enum of that grave's real evidence IDs, and code drops anything else anyway. The answer becomes "The spirits are silent." when it cites nothing real, when Gemma itself says the evidence is silent, or when it contains any number that isn't in the evidence it cites . A reply that loops until the 400-token cap gets one retry with a new seed, then silence. selftest builds a small haunted git repo (a dead file, a dead function, a rename, a binary, a skipped folder) and checks what the finder digs up, the citation guard, the number check and the receipts.
