Three bugs, three walls Chrome's sandbox design treats code in a sandboxed process as possibly hostile, so web content runs inside a sandbox, and V8 adds its own sandbox around its heap. A full chain has to get through every wall. Brendan Dolan-Gavitt's write-up lists the three stages: Stage Component Bug What it gave 1 V8's Maglev compiler A mutable HeapNumber reused during deoptimization Read and write inside V8's pointer-compression cage 2 Blink's animated-WebP decoder Time-of-check/time-of-use: cached frame geometry, swapped bytes after an ArrayBuffer transfer One chosen native write outside the cage 3 Crashpad on Windows A short-read retry that trusted a suspended renderer's page protections Code execution in the unsandboxed crash handler GBHackers' summary lists the fixes as XBOW describes them: stop reusing mutable HeapNumbers, keep WebP output buffers inside bitmap bounds, and cap Crashpad retries at the original request length.
