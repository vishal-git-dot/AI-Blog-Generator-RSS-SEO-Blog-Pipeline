# x402 Explained: HTTP-Native Micropayments for AI Agents (With Real Code)

## Overview

x402 Explained: HTTP‑Native Micropayments for AI Agents (With Real Code) Why “HTTP‑Native” Matters for Autonomous Agents Autonomous AI agents are built to act without constant human oversight, but they still need to acquire services—data feeds, compute, storage, or even other agents—on demand. Traditional payment flows (OAuth tokens, API keys, invoicing) introduce out‑of‑band steps, secret management, and latency that clash with the “fire‑and‑forget” model agents prefer. x402 is a HTTP status code extension that lets a server signal “payment required” inside the normal request/response cycle. The client can then attach a micropayment (usually in a stablecoin like USDC) directly to the HTTP header or body, retry the request, and receive the resource—all without leaving the HTTP protocol. For agents that already speak HTTP, this means payment becomes just another header, not a separate integration project. The Protocol in a Nutshell Element Description Status Code 402 Payment Required (existing IANA‑reserved code) Response Header X-Payment-Headers: <JSON‑encoded spec> – tells the client what to pay, where, and how much Client Payment A signed transaction (e.g., Ethereum L2 USDC transfer) placed in the X-Payment request header or as a JSON payload in the body Verification Server validates the transaction against the spec (amount, token, recipient, nonce) before serving the resource Idempotency Clients can include an Idempotency-Key header; servers cache successful payments to avoid double‑charging Because the spec lives in headers, any HTTP client—fetch, Axios, httpx , even a raw TCP socket—can participate.
