# RSI in Python: Wilder’s Formula and Live Candle Updates

## Overview

Two charts can show the same market, the same interval and RSI(14), yet disagree by several points. Before changing the formula, check where each calculation begins and whether the last candle is still moving. RSI in Python is straightforward once those choices are explicit. Calculate gains and losses from consecutive closes, initialise their averages, and apply Wilder's smoothing to each new completed bar. Keep updates to the forming candle separate from that permanent state. This guide builds the calculation from a small worked example, then connects it to historical bars and real-time prices from SiftingIO. The example prices are invented so every number can be checked. They are not market observations or a trading result. What RSI measures The Relative Strength Index compares the size of recent upward and downward price changes. It expresses that balance on a scale from 0 to 100. It does not compare one asset with another, despite the words “relative strength”. The usual input is the closing price. RSI(14) uses a smoothing period of 14 bars, which might mean 14 minutes, 14 hours or 14 daily observations depending on the chart. Volume, highs and lows are not inputs to the standard close-based calculation. The familiar 30 and 70 levels are interpretation thresholds, not instructions to buy or sell. A persistent trend can keep RSI near an extreme. Fidelity's RSI guide describes the indicator and its conventional interpretation. For a data application, the first job is simpler: produce a reproducible number and make its status clear. Wilder's RSI formula For each pair of consecutive closes, split the price change into two non-negative values: change = current close minus previous close gain = max(change, 0) loss = max(negative change, 0) For a period of n, seed the calculation with the arithmetic mean of the first n gains and the first n losses. That requires n + 1 closes. Fourteen closes contain only thirteen changes, so they cannot produce this implementation's first RSI(14). After the seed, update the two averages as follows: new average gain = ((previous average gain × (n − 1)) + current gain) ÷ n new average loss = ((previous average loss × (n − 1)) + current loss) ÷ n RSI = 100 × average gain ÷ (average gain + average loss) The last expression is algebraically equivalent to the usual relative-strength formula when the denominator is positive. It also handles an average loss of zero without dividing by that loss first. Notice that the averages keep information from earlier bars. Wilder's calculation does not discard the oldest observation and recompute a simple average of just the latest 14 changes at every step. That rolling-average variant gives a different indicator. Round the displayed result, not the state carried into the next bar. A small Python implementation The following class needs only Python's standard library. Call update once per completed bar, in chronological order. Call preview for a possible close of the current candle; it calculates from a copy and leaves the committed state intact. """Educational Wilder RSI implementation. Inputs must be ordered closed bars.""" from copy import copy from math import isfinite class WilderRSI : def __init__ ( self , period = 14 ) : if isinstance ( period , bool ) or not isinstance ( period , int ) or period < 1 : raise ValueError ( "period must be a positive integer" ) self . period = period self . previous = None self . changes = 0 self . gain = 0.0 self . loss = 0.0 def update ( self , close ) : close = float ( close ) if not isfinite ( close ) or close <= 0 : raise ValueError ( "close must be finite and positive" ) if self . previous is None : self . previous = close return None change = close - self . previous self . previous = close up = max ( change , 0.0 ) down = max ( - change , 0.0 ) self . changes += 1 if self . changes <= self . period : self . gain += up self . loss += down if self . changes < self . period : return None self . gain /= self . period self . loss /= self . period else : n = self . period self . gain = ( self . gain * ( n - 1 ) + up ) / n self . loss = ( self . loss * ( n - 1 ) + down ) / n total = self . gain + self . loss return None if total == 0 else 100 * self . gain / total def preview ( self , candidate_close ) : return copy ( self ) . update ( candidate_close ) An all-flat series makes both smoothed averages zero. This implementation returns None because that ratio is undefined. Some libraries choose a numeric convention instead. Match that convention deliberately when comparing implementations. The input checks reject non-finite and non-positive closes. This example targets instruments with positive prices, such as a normal forex pair. It is not a universal validator for every financial contract. Run the worked example: prices = [ 100 , 102 , 101 , 103 , 102 , 104 , 103 , 105 ] state = WilderRSI ( period = 5 ) for bar , close in enumerate ( prices , start = 1 ) : value = state . update ( close ) print ( bar , close , None if value is None else round ( value , 4 ) ) The first five results are None . The final three are 75.0, 64.8649 and 73.7374. A steadily rising sequence produces 100 after its seed; a steadily falling sequence produces 0. Why a pandas RSI can disagree A common implementation smooths gains and losses with ewm(alpha=1/14, adjust=False) . The decay factor is right for Wilder's recurrence, but the initial state still matters. According to the pandas documentation , the recursive calculation starts from the first observation. min_periods=14 controls when a result becomes visible. It does not replace that initial observation with the arithmetic mean of the first 14 changes. Also, span=14 uses a different decay factor from alpha=1/14 . These settings explain many differences that look like bad market data. If matching another chart is the goal, compare its seed, smoothing method and history start before rounding the output to fewer decimals. The explicit loop above makes the seed inspectable. Update a live RSI without counting a candle twice WebSocket messages arrive more often than candles close. Updating a 14-period RSI for every tick would make its period count ticks rather than bars. For an hourly chart, keep the committed state at the last completed hour. Use the latest valid price as the candidate close for the forming hour and call preview . Each new candidate starts from that same committed state. In the five-period example, stop after bar 6, whose close is 104 and RSI is 75.
