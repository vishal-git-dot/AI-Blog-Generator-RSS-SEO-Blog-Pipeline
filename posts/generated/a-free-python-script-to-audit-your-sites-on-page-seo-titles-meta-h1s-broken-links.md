# A Free Python Script to Audit Your Site's On-Page SEO (Titles, Meta, H1s, Broken Links)

## Overview

Paid SEO crawlers are great, but sometimes you just want a quick answer to a few simple questions. Does every page have a title of sensible length? Is any page missing a meta description? Are there pages with zero or several H1 tags? Which links are broken? You can answer all of these with about 100 lines of Python. In this post we'll build a small crawler that walks your site, checks the basics on every page, and writes the results to two CSV files you can open in Excel or Google Sheets. What the Script Checks For each HTML page on your domain: Title tag: whether it exists and is roughly 30–60 characters Meta description: whether it exists and is roughly 70–160 characters H1 tags: exactly one per page Canonical tag: whether one is present Image alt text: a count of images with no alt Links: every outgoing link (internal and external) is checked, and anything returning 4xx, 5xx or a connection error is flagged as broken The length ranges are common rules of thumb, not hard rules from Google. Adjust them to suit your site. The script does a breadth-first crawl, starting from the URL you give it. It uses a deque as a queue and a seen set so each page is visited only once. Only links on the same domain ( netloc ) are added to the queue, so it won't wander off and crawl the whole internet. MAX_PAGES caps the crawl, so you can run a quick 20-page check or a fuller 500-page pass. Parsing. BeautifulSoup reads each page, and audit_page() collects issues as plain strings. That makes it trivial to add your own checks. For example, you could flag noindex robots meta tags or pages missing Open Graph tags. Link checking. Every absolute link is checked once. The mutable default argument cache={} is usually a Python gotcha, but here it's used on purpose as a simple memo, so a link that appears in your footer on 300 pages is requested only once. HEAD requests are cheap. Some servers reject them with 405 or 403, so the script falls back to a streamed GET. Output. You get two files: seo_report.csv : one row per page, with status, title, meta description length and a semicolon-separated list of issues broken_links.csv : which page contains the broken link, the link itself, and its status Running It python seo_audit.py https://example.com 50 The second argument is the page limit (default 50). You'll see progress in the terminal: [1] https://example.com/ -> 2 issue(s) [2] https://example.com/about -> 0 issue(s) ... Audited 50 pages, found 3 broken links. Wrote seo_report.csv and broken_links.csv Open the CSV, sort by the issues column, and you have a to-do list. Things to Keep in Mind Be polite. This script doesn't throttle requests. On a small shared host, add time.sleep(0.5) in the main loop. Only crawl sites you own or have permission to audit. JavaScript sites. requests sees only the raw HTML. If your site renders content client-side (some React or Vue apps), titles and H1s may appear missing. You'd need a headless browser such as Playwright for those. External link false positives. Some sites (LinkedIn is a classic) return 999 or 403 to bots even though the page works in a browser. Double-check external "broken" links by hand before you remove them. robots.txt. The script doesn't read robots.txt . If you crawl beyond your own site, use urllib.robotparser to respect it. Speed. Link checking is sequential, so large sites take a while. A concurrent.futures.ThreadPoolExecutor around check_link is an easy upgrade. For small blogs, portfolios and side projects, though, a script like this catches most on-page problems in minutes, and you can see exactly what it checks.
