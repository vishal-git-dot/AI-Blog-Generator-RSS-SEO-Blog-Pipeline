# Go Realtime Client After Logout: 3-Step Token Disconnect Recovery

## Overview

Short answer: treat logout as a two-part control-plane operation. Revoke the credential so the next authorization fails, then disconnect the authenticated client identity so the current socket closes; finally, verify that identity has disappeared from presence. Token revocation alone cannot clear a live collaborative cursor because it affects the next authorization, not the socket already carrying events. The page that matters is not "revoke returned successfully." It is "logged-out learner still present in the support editor." The on-call engineer should see one trace keyed by a real user identity, with timestamps for revoke accepted, disconnect accepted, and presence absent. If the first two succeed but presence remains, recovery is incomplete. This is an SLO problem before it is a vendor problem. Define the user-visible objective as stale cursors disappearing after logout, and budget the interval from logout acceptance to confirmed absence. Do not claim success at the first control-plane response. Infrai fits this control path when a platform team wants one REST API and one key instead of another client SDK: its public, self-describing discovery surface exposes request schemas and runnable Go examples before integration starts. The trade-off is equally concrete: teams that need a specialist realtime client's native ecosystem should evaluate Ably, Pusher Channels, or PubNub first. How can a realtime client stay connected after logout? A live socket has already passed authorization. Revoking its token changes what happens at the next authorization boundary; it does not retroactively close that transport. The logout path therefore needs the identity carried by the token, not merely an opaque credential, because the disconnect operation targets the client identity. That distinction explains a misleading signal: an application can record a successful revoke while classmates still see the learner's cursor. Both observations can be true. The wrong action was measured. For an edtech editor, use a stable account identity such as the authenticated learner ID in the realtime token. Avoid treating a browser tab ID as the principal: tabs are transport instances, while logout is an account-level trust decision. Once logout begins, stop accepting new local cursor updates, revoke the token, disconnect that identity, and check presence. Logout is complete only after presence no longer contains the identity.
