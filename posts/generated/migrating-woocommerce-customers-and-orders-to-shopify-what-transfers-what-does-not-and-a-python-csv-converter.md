# Migrating WooCommerce customers and orders to Shopify: what transfers, what does not, and a Python CSV converter

## Overview

Moving a store from WooCommerce to Shopify sounds like one job. In practice it's three: products, customers and orders, and each one moves differently. Products are the easy part. Customers come across with some gaps you need to plan for. Orders are where most people get stuck, because the tool they used for the first two doesn't handle them. This post covers what transfers, what doesn't, and a short Python script that turns a WooCommerce customer export into a file Shopify's customer import accepts. What transfers and what doesn't? Transfers cleanly: names, email addresses, a default address, phone numbers (if they're in a format Shopify accepts), company names, and anything you choose to carry over as tags or notes. Doesn't transfer: passwords. WordPress stores password hashes, not passwords, and Shopify can't use those hashes. Every imported customer has to set up access again. With Shopify's classic customer accounts you send account invites so they can set a new password. With the newer customer accounts there are no passwords at all; customers sign in with a one-time code sent to their email, so the "reset your password" problem goes away. Either way, tell customers before launch so the change doesn't look like a security problem. Needs a different tool: historical orders. The CSV import in the Shopify admin covers products and customers. It doesn't import past orders. For those you need an app, such as Shopify's Store Migration app or Matrixify, or a script against the Shopify Admin API. Keep the old WooCommerce order number somewhere on each imported order (in the order name, a tag or a note) so your support team can find an order when a customer quotes the old number. Depends on third parties: subscriptions and saved cards. Saved payment tokens belong to your payment gateway, not to WooCommerce, and recurring billing belongs to your subscription plugin. Whether active subscriptions can carry on without customers re-entering card details depends on the gateway and the Shopify subscription app you pick. Ask both before you set a launch date. Easy to miss: guest customers. People who checked out as guests in WooCommerce don't have user accounts, so a user-based export leaves them out. Their details only exist on their orders. Decide whether you want them as Shopify customers, and only mark them as subscribed if you have a record of consent. The customer export WooCommerce stores billing details as user meta with keys like billing_first_name , billing_city and billing_country . Most export plugins can output these as columns. This sample uses those names plus a marketing_opt_in column from a newsletter plugin. An empty opt-in column means you don't know, and not knowing isn't consent. In the UK, PECR and UK GDPR set the rules for marketing email consent, and Canada's CASL expects you to be able to show consent, so if the record isn't there, leave it as "no". SMS marketing is always "no". Email consent doesn't cover text messages. Collect SMS consent separately on Shopify. Phones without a country code go to the note. The WooCommerce ID goes in the note. It's the link back to the old system when you match orders or answer a support question. State codes pass straight through. WooCommerce uses short codes like ON and NSW for countries where Shopify expects a province code. UK stores often leave the county empty, which is fine. Before you import for real Import a test file of 10 to 20 customers into a development store and check a few customer records by hand. Count the rows in and out. The script prints what it skipped; make sure every skip has a reason you accept. Import customers before orders, so the order import can attach each order to an existing customer by email. Plan the customer email: why the store moved, how to sign in, and that order history is still there (if you imported it). Customer and order data is the part of a migration you can't redo cheaply after launch, so it's worth a dry run. FAQ Can I move customer passwords from WooCommerce to Shopify? No. WordPress only keeps password hashes, and Shopify can't use them. Customers either set a new password from an account invite or, with Shopify's newer customer accounts, sign in with a one-time code by email. Can I import past orders with the Shopify admin CSV import? No. The admin import handles products and customers. Use a migration app such as Store Migration or Matrixify, or the Admin API, for historical orders. Will subscribers keep their subscriptions after the move? It depends on your payment gateway and the subscription app you choose on Shopify. Check with both before launch, and have a plan for customers who need to re-enter card details.
