# Finding what broke: observability, evaluation, optimization

## Overview

An agent that behaved correctly on launch day is silently making bad decisions two months later. Nobody changed the code; the world it judges just drifted away from the prompt it was given. This use case builds that failure on purpose: an expense-audit agent whose system prompt carries one stale sentence, then walks the full quality loop Amazon Bedrock AgentCore provides — observe the spans, evaluate the traces, cluster the failures, optimize the prompt, ship the fix as a configuration bundle, and prove it with an A/B test and a CI gate. Every number below was measured in one account, us-east-1 . The use case The travel desk at Northwind Gear runs an expense auditor: a receipt goes in, a reimbursement decision comes out. Finance does not complain that it crashes — they complain that international hotel bills keep coming back approved at suspiciously round numbers, and nobody can say which of the two-month-old instructions is to blame. What AgentCore does here Four capabilities carry the loop. Runtime: hosts the Strands agent and streams its decisions; the prompt it runs comes from a configuration bundle, not from the code. Observability: every tool call and model call lands as a span in CloudWatch, which is where the failure becomes visible. Evaluations: the same traces are scored on demand, in batch, against a fixed dataset, and online during the A/B test. Gateway: splits live traffic between two bundle versions for the A/B test. Optimization — the recommendation job that rewrites the system prompt from trace evidence — sits outside the core nine and is listed here for completeness. Every receipt amount is already in USD; report every total in USD. The receipts table disagrees: three of the seven are EUR or GBP. A prompt this stale is exactly what drifts into production, because nothing crashes — the model just follows an instruction that stopped being true. The fix travels as data, not code. A hook re-reads the active bundle before every model call: def apply_bundle_prompt ( event : BeforeModelCallEvent ) -> None : bundle = BedrockAgentCoreContext . get_config_bundle () prompt = bundle . get ( " system_prompt " ) if prompt : event . agent . system_prompt = prompt The gateway injects the bundle reference as a W3C baggage header, so the same session can run under different prompt versions during an A/B test. Without this hook a prompt change would be a code deploy, and there would be nothing to split traffic between. The third piece is invisible until it fails. Tracing needs the OpenTelemetry distro in the runtime dependencies: dependencies = [ " strands-agents " , # get_config_bundle() on BedrockAgentCoreContext needs 1.8 or newer " bedrock-agentcore>=1.8 " , # 1.25.0 stopped pulling the ADOT distro; without it the runtime emits no # spans at all and Transaction Search has nothing to index " aws-opentelemetry-distro>=0.18.0 " , ] Deploy it Seven resources, declared then deployed once — a gateway, two evaluators, two online evaluation configs, the bundle, the dataset: agentcore add gateway --name expense-gateway --protocol-type NONE --authorizer-type NONE agentcore add evaluator --name currency_guard --level TRACE \ --type llm-as-a-judge --model deepseek.v3.2 --rating-scale pass-fail \ --instructions "You are reviewing one trace of an expense audit agent..." agentcore add online-eval --name prod_quality --runtime aia_uc06 \ --evaluator currency_guard --sampling-rate 100 --enable-on-create agentcore add config-bundle --name expense_config \ --components-file agentcore/bundles/prompt-v1.json --branch main \ --commit-message "production prompt as it has run for two months" agentcore add dataset --name expense_audit_set \ --schema-type AGENTCORE_EVALUATION_PREDEFINED_V1 \ --description "Fixed audit scenarios with known-correct answers" agentcore deploy -y --target default Now audit an EUR receipt against the stale prompt: agentcore invoke --runtime aia_uc06 \ --session-id qloop-prod-02-r4107-audit-run-2026 \ --prompt "Audit receipt R-4107 for reimbursement. The failure analysis clusters 17 sessions and hands back one dominant pattern with a fix type: agentcore run insights -r aia_uc06 --lookback-days 1 \ -n baseline_failure_analysis --wait agentcore view insights baseline_failure_analysis-375c7e1293 --json The recommendation job consumes that insight and rewrites the prompt. It refuses a pass-fail evaluator — optimization needs numeric scores — and succeeds with Builtin.Correctness : agentcore run recommendation --type system-prompt -r aia_uc06 -e currency_guard \ --prompt-file app/aia_uc06/system-prompt.md \ --from-insights baseline_failure_analysis-375c7e1293 -n currency_fix --wait agentcore run recommendation --type system-prompt -r aia_uc06 -e Builtin.Correctness \ --prompt-file app/aia_uc06/system-prompt.md \ --from-insights baseline_failure_analysis-375c7e1293 -n currency_fix3 --wait The optimizer's diagnosis is precise — it names the traces, the fabricated 1:1 equivalence, and the blanket assertion — but its rewrite adds an approval gate that would break this single-turn agent. Take the diagnosis, apply the minimal edit, and commit it as a second, immutable bundle version: aws bedrock-agentcore-control update-configuration-bundle --region us-east-1 \ --cli-input-json file:///tmp/update-bundle-v2.json agentcore run ab-test -n expense_ab_01 -g expense-gateway \ --control-bundle expense_config --control-version f45629ba-e409-46b7-80b8-ce1858319573 \ --treatment-bundle expense_config --treatment-version d4c45b72-99ec-4d39-a60b-b5a1541f68d5 \ --online-eval prod_score --control-weight 50 --treatment-weight 50 Twenty-eight audited requests go through the gateway URL, split by baggage headers; twenty-six of them come back scored online by the numeric evaluator — twelve control, fourteen variant. The report is one command: agentcore view ab-test aiauc06_expense_ab_01-227c8af53d --json Quality went from 2.0 to 4.0 on a 5-point scale, and the report says the difference is real, not sampling noise. That measurement is what a CI gate can enforce. The committed workflow runs the same batch evaluation on every pull request that touches the use case and fails below the floor: agentcore run batch-evaluation --runtime aia_uc06 -e Builtin.Correctness \ -n gate_probe --lookback-days 1 --wait --json A red check blocks the merge; the pass at 0.678 over 45 sessions and the block at a raised 0.900 floor show both paths. Teardown empties the contract, then reconciles the stack down: agentcore remove all -y agentcore deploy -y --target default agentcore status remove all -y rewrites agentcore/agentcore.json and empties agentcore/aws-targets.json ; restore both from git before deploying again. What it produced The loop closed with measured numbers at every hop: 22 tool spans with zero conversions exposed the failure, three offline evaluation modes scored it (0.00 on the failing session, 0.50 average across eleven), insights attributed 8 of 17 sessions to one root cause and named the fix type, the recommendation turned that into a prompt edit, and the A/B report moved quality from 2.0 to 4.0 with p equal to 0.00043. The versioning is real too: the runtime carries five versions with DEFAULT advancing on deploy, the prod endpoint stays pinned to version 1 as the A/B baseline, and the prompt moved from bundle version f45629ba to d4c45b72 with a commit message — no code deploy anywhere in the fix. Troubleshooting No spans at all, and evaluation reports No session spans found : releases of bedrock-agentcore from 1.25.0 no longer pull the ADOT distro. Add aws-opentelemetry-distro>=0.18.0 or nothing reaches aws/spans . Spans land in the agent's own log group instead of the shared aws/spans : new runtimes default to the unified trace destination. Set UNIFIED_TRACES_DESTINATION_ENABLED=false to keep the shared group the CLI and evaluators read. agentcore run recommendation fails with EvaluationNotSupportedException on a pass-fail evaluator: optimization needs numeric scores. Register a 1-to-5 rating-scale evaluator and point the job at it. Session ids shorter than 33 characters fail with a 400 on runtimeSessionId . Takeaways Observability is the difference between "the agent seems wrong" and a sentence you can quote: 22 tool spans with zero convert_currency calls is a finding, not an opinion. Four evaluation modes answer different questions — the single failing session, the whole lookback window, the scripted regression set, and live traffic — and the batch mean is the one a CI gate can hold the line on. Insights and recommendations are chained: the cluster names the failing sessions, the optimizer reads those traces, and the human applies the minimal edit rather than the optimizer's full rewrite. Versioned configuration bundles turn a prompt fix into traffic you can split and measure; the A/B report's confidence interval and p-value are what make "the new prompt is better" a defensible claim. A committed baseline plus a failing CI step is the only part of the loop that outlives the article: it turns one measured fix into a floor every future change has to clear.
